## Ý chính

Một lớp bài toán tối ưu hay đếm có thể giải bằng đệ quy rất đẹp nhưng chạy mãi không xong, vì đệ quy giải đi giải lại **cùng một bài con** hàng triệu lần. Ở bài [Big-O & Complexity](/docs/dsa/complexity), Fibonacci đệ quy gọi hàm 2.692.537 lần cho `n = 30` trong khi chỉ có 31 bài con khác nhau; thêm một cái từ điển nhớ kết quả là xong. <Term>Dynamic programming</Term> (quy hoạch động) là việc làm điều đó một cách có hệ thống: tách bài toán thành các bài con, **giải mỗi bài con đúng một lần**, lưu lại, và dùng lại.

Hai điều kiện để áp dụng được: **bài con chồng lấp** (cùng một bài con xuất hiện nhiều lần, nếu không thì chia để trị thuần như merge sort đã đủ) và **cấu trúc con tối ưu** (lời giải tối ưu của bài lớn được ghép từ lời giải tối ưu của bài con). Phần khó nhất không phải code mà là **định nghĩa đúng "trạng thái"**: bảng của bạn lưu cái gì. Khi đã định nghĩa được, công thức truy hồi và vòng lặp gần như tự ra.

Bài đi theo trình tự: dấu hiệu nhận biết và quy trình năm bước; đổi tiền (ví dụ kinh điển nhất, có bảng tính tay, so đệ quy với bảng và so với tham lam); knapsack, LCS và edit distance với bảng đầy đủ, truy vết lời giải; các cách tối ưu (bộ nhớ, LIS ở `O(n log n)`); và top-down so với bottom-up. Mọi code là Python 3.13 chạy thật, mọi số khớp với bảng tính tay. Bài này cần kiến thức đệ quy và recurrence ở [Big-O & Complexity](/docs/dsa/complexity), và dùng [mảng](/docs/dsa/arrays-linked-lists), [bảng băm](/docs/dsa/hash-tables) (memo), tìm nhị phân.

## Quy trình năm bước

Hầu hết bài DP giải được bằng cùng một khuôn:

1. **Định nghĩa trạng thái**: `dp[...]` nghĩa là gì, bằng một câu tiếng Việt chính xác. Ví dụ "số đồng ít nhất để trả đúng `a` đồng".
2. **Công thức truy hồi**: `dp` của trạng thái này tính từ `dp` của những trạng thái **nhỏ hơn** thế nào (các lựa chọn ở bước cuối).
3. **Trường hợp cơ sở**: trạng thái nhỏ nhất, đáp án không cần đệ quy (`dp[0] = 0`).
4. **Thứ tự tính**: phải tính trạng thái mà công thức phụ thuộc trước. Với đệ quy có nhớ thứ tự này tự động; với bảng thì phải tự sắp (thường là tăng dần).
5. **Đáp án** nằm ở ô nào, và **truy vết** (nếu cần cả lời giải chứ không chỉ giá trị): lưu lại lựa chọn đã dẫn tới giá trị tối ưu ở mỗi ô, rồi lần ngược từ ô đáp án.

Chi phí luôn là **số trạng thái nhân chi phí xử lý một trạng thái**. Đây là cách đọc độ phức tạp của mọi bài DP.

## Đổi tiền: số đồng ít nhất

Cho các loại tiền `coins` và số tiền `amount`, trả đúng `amount` bằng **ít đồng nhất**. Gọi `dp[a]` là số đồng ít nhất để trả đúng `a`. Lựa chọn ở bước cuối là đồng nào `c` được dùng: sau khi dùng nó còn phải trả `a - c`, nên

```text
dp[0] = 0
dp[a] = 1 + min( dp[a - c] )  với mọi đồng c <= a        (dp[a] = ∞ nếu không trả được)
```

Tính tay cho `coins = [1, 2, 5]` và `a` từ 0 tới 11. `dp[1] = 1 + dp[0] = 1`; `dp[2] = 1 + min(dp[1], dp[0]) = 1`; `dp[3] = 1 + min(dp[2], dp[1]) = 2`; `dp[5] = 1 + min(dp[4], dp[3], dp[0]) = 1`; ... `dp[11] = 1 + min(dp[10], dp[9], dp[6]) = 1 + min(2, 3, 2) = 3`. Ba cách cài đặt, cùng công thức:

- **đệ quy thuần**: `naive`, mỗi lời gọi thử mọi đồng và gọi lại bài con;
- **top-down có nhớ** (memoization): đệ quy y hệt nhưng lưu kết quả vào từ điển; thứ tự tính tự phát sinh;
- **bottom-up** (bảng, tabulation): vòng lặp tăng dần `a`, mỗi ô chỉ dùng các ô nhỏ hơn đã tính. Thêm mảng `choice` để truy vết.

```python
# Đổi tiền: số đồng ít nhất để trả đủ amount. Ba cách: đệ quy thuần, top-down có nhớ, bottom-up.
import sys, time
sys.setrecursionlimit(10000)
INF = float("inf")

calls = 0
def naive(coins, amt):
    global calls
    calls += 1
    if amt == 0: return 0
    best = INF
    for c in coins:
        if c <= amt: best = min(best, 1 + naive(coins, amt - c))
    return best

def topdown(coins, amt):
    memo, sub = {}, [0]
    def f(a):
        if a == 0: return 0
        if a in memo: return memo[a]
        sub[0] += 1
        memo[a] = min((1 + f(a - c) for c in coins if c <= a), default=INF)
        return memo[a]
    r = f(amt); return r, sub[0]

def bottomup(coins, amt):
    dp = [0] + [INF] * amt
    choice = [0] * (amt + 1)                      # đồng nào được chọn ở trạng thái a: để truy vết
    for a in range(1, amt + 1):
        for c in coins:
            if c <= a and dp[a - c] + 1 < dp[a]:
                dp[a] = dp[a - c] + 1; choice[a] = c
    used, a = [], amt
    while a > 0 and dp[amt] < INF: used.append(choice[a]); a -= choice[a]
    return dp, used

def greedy(coins, amt):
    used = []
    for c in sorted(coins, reverse=True):
        while amt >= c: amt -= c; used.append(c)
    return used if amt == 0 else None

coins = [1, 2, 5]
dp, used = bottomup(coins, 11)
print("bảng dp cho coins = [1, 2, 5], amount 0..11:")
print("  a  :", " ".join(f"{a:>2}" for a in range(12)))
print("  dp :", " ".join(f"{x:>2}" for x in dp), "  <- dp[a] = 1 + min(dp[a-1], dp[a-2], dp[a-5])")
print("  truy vết 11 =", used)

print()
print(f"{'amount':>7} | {'đệ quy thuần: số lần gọi':>26} | {'top-down: số bài con':>21} | {'bottom-up: số ô':>16} | kết quả")
for amt in (10, 20, 25, 30):
    calls = 0; r1 = naive([1, 2, 5], amt); c1 = calls
    r2, s2 = topdown([1, 2, 5], amt)
    d, _ = bottomup([1, 2, 5], amt)
    assert r1 == r2 == d[amt]
    print(f"{amt:>7} | {c1:>26,} | {s2:>21} | {amt + 1:>16} | {r1}")

print()
print("tham lam có đủ không?")
for cs, amt in (([1, 5, 10, 25], 63), ([1, 3, 4], 6), ([1, 5, 12], 15)):
    d, used = bottomup(cs, amt)
    g = greedy(cs, amt)
    print(f"  coins {cs}, amount {amt}: tham lam {g} ({len(g)} đồng) | DP {used} ({d[amt]} đồng)")

print()
big = 100_000
t = time.perf_counter(); d, _ = bottomup([1, 5, 10, 25, 50, 100], big); dt = time.perf_counter() - t
print(f"bottom-up với amount {big:,} và 6 loại tiền: {dt*1000:.0f} ms (số ô {big + 1:,} x 6 phép chọn)")
try:
    topdown([1, 5, 10, 25, 50, 100], big)
except RecursionError:
    print("top-down cùng bài: RecursionError (độ sâu đệ quy = amount / đồng nhỏ nhất)")
```

Bảng đầu khớp phép tính tay: `dp[11] = 3`, truy vết ra `[1, 5, 5]` (tổng 11, ba đồng). Phần bảng tiếp theo là điểm cốt lõi của DP:

| `amount` | Đệ quy thuần (số lần gọi) | Top-down (số bài con) | Bottom-up (số ô) |
|---|---|---|---|
| 10 | 309 | 10 | 11 |
| 20 | 64.207 | 20 | 21 |
| 25 | 924.876 | 25 | 26 |
| 30 | 13.322.380 | 30 | 31 |

Mỗi lần `amount` tăng 5 thì số lần gọi của đệ quy thuần tăng khoảng 14 lần: **mũ**. Còn số bài con **khác nhau** chỉ tuyến tính (đúng bằng `amount`). Có memo thì mỗi bài con được giải một lần, chi phí giảm từ mũ xuống `O(amount × số loại tiền)`, ở ví dụ trên là 30 phép chọn cho 30 ô thay vì 13 triệu lời gọi.

### Top-down hay bottom-up

| | Top-down (memo) | Bottom-up (bảng) |
|---|---|---|
| Viết | gần với công thức, chỉ cần thêm cache | phải tự xác định thứ tự điền |
| Chỉ tính bài con **cần** | có (tính theo nhu cầu) | không (điền hết bảng) |
| Độ sâu đệ quy | có giới hạn (stack) | không |
| Tối ưu bộ nhớ (chỉ giữ vài hàng) | khó | dễ |
| Tốc độ | chậm hơn do chi phí gọi hàm | nhanh hơn |

Hai dòng cuối trong output minh hoạ rõ: bottom-up giải `amount = 100.000` với 6 loại tiền trong **35 ms**; top-down cùng bài **hỏng với `RecursionError`**, vì độ sâu đệ quy bằng `amount` chia cho đồng nhỏ nhất, vượt xa giới hạn stack của Python. Vì thế dù viết công thức bằng đệ quy cho dễ nghĩ, nên cài bằng bảng khi trạng thái có thể sâu hoặc nhiều.

## Tham lam: khi nào đủ, khi nào không

Đổi tiền còn có cách "tham lam": luôn lấy đồng lớn nhất còn vừa. Hàng cuối của output cho thấy nó đúng với hệ tiền chuẩn và **sai** với hệ khác:

| Hệ tiền | `amount` | Tham lam | DP (tối ưu) |
|---|---|---|---|
| `1, 5, 10, 25` | 63 | 6 đồng | 6 đồng |
| `1, 3, 4` | 6 | `[4, 1, 1]` = 3 đồng | `[3, 3]` = **2 đồng** |
| `1, 5, 12` | 15 | `[12, 1, 1, 1]` = 4 đồng | `[5, 5, 5]` = **3 đồng** |

Hệ tiền thật (cent của Mỹ) có tính chất đặc biệt khiến tham lam đúng, nhưng thiếu điều đó thì không. Tham lam chỉ đúng khi bài toán có **tính chất lựa chọn tham lam**: tồn tại một lựa chọn "tốt nhất ngay lúc này" luôn nằm trong một lời giải tối ưu nào đó, thường chứng minh bằng **lập luận hoán đổi** (exchange argument): lấy một lời giải tối ưu bất kỳ, đổi một phần của nó sang lựa chọn tham lam mà không làm tệ đi. Ví dụ tham lam đúng: xếp lịch nhiều hoạt động nhất khi chọn hoạt động kết thúc sớm nhất; Huffman; Kruskal và Prim ở [Graph](/docs/dsa/graphs). Khi không chắc, **dùng DP**: nó thử mọi lựa chọn nên không cần chứng minh thêm điều gì, chỉ cần định nghĩa trạng thái đúng.

## Knapsack, LCS và edit distance

Ba bài này cùng khuôn: bảng hai chiều, mỗi ô là một lựa chọn trong số ít, kèm truy vết.

### Knapsack 0/1

Có `n` món, món `i` nặng `w_i` và giá trị `v_i`; túi chứa tối đa `W`. Mỗi món lấy hoặc không (0/1), tối đa hoá tổng giá trị. Gọi `dp[i][w]` là giá trị lớn nhất khi chỉ xét `i` món đầu với sức chứa `w`. Với món `i` có hai lựa chọn: **bỏ** (`dp[i-1][w]`) hoặc **lấy** nếu vừa (`dp[i-1][w - w_i] + v_i`), chọn lớn hơn. Truy vết: món `i` được lấy nếu `dp[i][w]` khác ô ngay phía trên.

### Longest Common Subsequence (LCS)

Dãy con chung dài nhất của hai chuỗi (không cần liền nhau). `dp[i][j]` là độ dài LCS của `i` ký tự đầu của `a` và `j` ký tự đầu của `b`. Nếu hai ký tự cuối bằng nhau, nó thuộc LCS: `dp[i-1][j-1] + 1`. Nếu khác nhau, bỏ một trong hai: `max(dp[i-1][j], dp[i][j-1])`. LCS là nền của `diff`.

### Edit distance (Levenshtein)

Số thao tác (chèn, xoá, thay một ký tự) ít nhất để biến chuỗi `a` thành `b`. `dp[i][j]` là khoảng cách giữa `i` ký tự đầu của `a` và `j` ký tự đầu của `b`; ba lựa chọn cho ký tự cuối: xoá `a[i-1]` (`dp[i-1][j] + 1`), chèn `b[j-1]` (`dp[i][j-1] + 1`), hoặc thay (`dp[i-1][j-1] + (a[i-1] != b[j-1])`, bằng nhau thì không tốn thao tác). Cơ sở: biến `i` ký tự thành rỗng cần `i` lần xoá; từ rỗng ra `j` ký tự cần `j` lần chèn.

```python
# Knapsack 0/1, LCS, edit distance: bảng đầy đủ, truy vết, tối ưu bộ nhớ.
def knapsack(items, W):
    """items = [(tên, khối lượng, giá trị)]. dp[i][w] = giá trị lớn nhất dùng i món đầu, sức chứa w."""
    n = len(items)
    dp = [[0] * (W + 1) for _ in range(n + 1)]
    for i in range(1, n + 1):
        _, wt, val = items[i - 1]
        for w in range(W + 1):
            dp[i][w] = dp[i - 1][w]                                  # không lấy món i
            if wt <= w: dp[i][w] = max(dp[i][w], dp[i - 1][w - wt] + val)   # lấy món i
    chosen, w = [], W
    for i in range(n, 0, -1):                                        # truy vết: món i được lấy nếu dp đổi so với hàng trên
        if dp[i][w] != dp[i - 1][w]: chosen.append(items[i - 1][0]); w -= items[i - 1][1]
    return dp, chosen[::-1]

def knapsack_1d(items, W):                                           # chỉ một hàng: duyệt w GIẢM dần
    dp = [0] * (W + 1)
    for _, wt, val in items:
        for w in range(W, wt - 1, -1): dp[w] = max(dp[w], dp[w - wt] + val)
    return dp[W]

def lcs(a, b):
    m, n = len(a), len(b)
    dp = [[0] * (n + 1) for _ in range(m + 1)]
    for i in range(1, m + 1):
        for j in range(1, n + 1):
            dp[i][j] = dp[i-1][j-1] + 1 if a[i-1] == b[j-1] else max(dp[i-1][j], dp[i][j-1])
    out, i, j = [], m, n
    while i and j:
        if a[i-1] == b[j-1]: out.append(a[i-1]); i -= 1; j -= 1
        elif dp[i-1][j] >= dp[i][j-1]: i -= 1
        else: j -= 1
    return dp, "".join(reversed(out))

def edit_distance(a, b):
    m, n = len(a), len(b)
    dp = [[0] * (n + 1) for _ in range(m + 1)]
    for i in range(m + 1): dp[i][0] = i                              # xoá i ký tự
    for j in range(n + 1): dp[0][j] = j                              # chèn j ký tự
    for i in range(1, m + 1):
        for j in range(1, n + 1):
            dp[i][j] = min(dp[i-1][j] + 1,                           # xoá a[i-1]
                           dp[i][j-1] + 1,                           # chèn b[j-1]
                           dp[i-1][j-1] + (a[i-1] != b[j-1]))        # thay (hoặc giữ nếu giống)
    ops, i, j = [], m, n
    while i or j:
        if i and j and dp[i][j] == dp[i-1][j-1] + (a[i-1] != b[j-1]):
            ops.append("giữ " + a[i-1] if a[i-1] == b[j-1] else f"thay {a[i-1]}->{b[j-1]}"); i -= 1; j -= 1
        elif i and dp[i][j] == dp[i-1][j] + 1: ops.append("xoá " + a[i-1]); i -= 1
        else: ops.append("chèn " + b[j-1]); j -= 1
    return dp, ops[::-1]

def show(dp, rows, cols, rl, cl):
    print("      " + "  ".join(f"{c:>2}" for c in cl))
    for i, r in enumerate(rows):
```

Đọc từng bảng:

- **Knapsack** (`W = 5`): cột `w = 3` hàng `i = 1` là 40, vì chỉ có laptop (nặng 3) vừa. Hàng `i = 3` (thêm đèn nặng 2, giá 25) ở `w = 5` thành 65: lấy laptop (3) cộng đèn (2) = 40 + 25. Hàng cuối `i = 4` (áo nặng 2, giá 15) không đổi vì không có chỗ cho nó mà có lợi hơn. Truy vết ra `['laptop', 'đèn']`, đúng 65. Bản `knapsack_1d` dùng **một hàng** và duyệt `w` **giảm dần**: nếu duyệt tăng dần, ô `dp[w - wt]` đã bị món hiện tại cập nhật và món được lấy hai lần (thành knapsack không giới hạn); duyệt giảm đảm bảo ô cần đọc vẫn mang giá trị của hàng trước.
- **LCS** (`AGGTAB` và `GXTXAYB`): bảng điền ra độ dài 4, truy vết ra `GTAB`. Nhìn đường chéo: các ô tăng giá trị nằm ở ký tự trùng (`G`, `T`, `A`, `B`).
- **Edit distance** (`kitten` → `sitting`): 3 thao tác, truy vết cho đúng ba bước (thay `k` thành `s`, thay `e` thành `i`, chèn `g`). Ô góc dưới phải của bảng là đáp án; mỗi ô dựa vào ba ô lân cận phía trên-trái.

Chi phí: knapsack `O(nW)`, LCS và edit distance `O(mn)`, cả hai đều **số ô nhân `O(1)` mỗi ô**. Lưu ý về knapsack: `O(nW)` phụ thuộc vào **giá trị** của `W`, không phải kích thước đầu vào (số bit của `W`); đó là thuật toán **giả đa thức**, và knapsack tổng quát là NP-hard. Khi `W` là số nhỏ (vài nghìn) thì rất thực dụng; khi `W` cỡ `10^12` thì bảng không dựng nổi.

## Tối ưu: bộ nhớ và độ phức tạp

### Chỉ giữ vài hàng

Mỗi ô LCS chỉ đọc hàng trước và ô bên trái, nên không cần cả bảng: giữ **hai hàng** là đủ, bộ nhớ giảm từ `O(mn)` xuống `O(n)`. Cái giá: mất khả năng truy vết bằng cách lần ngược bảng (có kỹ thuật Hirschberg khôi phục lời giải trong `O(n)` bộ nhớ nhưng tốn thêm công cài). Knapsack một hàng là cùng ý tưởng.

### LIS: từ O(n²) xuống O(n log n)

**Longest Increasing Subsequence**: dãy con tăng dài nhất. Cách DP chuẩn: `dp[i]` là độ dài dãy tăng dài nhất **kết thúc** tại `a[i]`; `dp[i] = 1 + max(dp[j])` với `j < i` và `a[j] < a[i]`. Hai vòng lồng, `O(n²)`. Có một cách khác thông minh hơn dựa vào nhận xét: với mỗi độ dài `k`, chỉ cần giữ **đuôi nhỏ nhất** có thể của dãy tăng dài `k`. Mảng `tails` luôn tăng, nên mỗi phần tử mới tìm nhị phân vị trí của nó: thay đuôi hoặc kéo dài. `O(n log n)`.

Cả hai cùng kết quả, đo thời gian khác nhau xa, và hai cách cài LCS (bảng hai hàng so với đệ quy memo bằng `lru_cache`):

```python
# LIS: O(n^2) bằng DP và O(n log n) bằng "patience"; và hiệu năng memo vs bảng với LCS.
import bisect, random, time, sys
from functools import lru_cache

def lis_n2(a):
    dp = [1] * len(a)
    for i in range(len(a)):
        for j in range(i):
            if a[j] < a[i] and dp[j] + 1 > dp[i]: dp[i] = dp[j] + 1
    return max(dp, default=0)

def lis_nlogn(a):
    tails = []                                    # tails[k] = đuôi nhỏ nhất của dãy tăng dài k+1
    for x in a:
        i = bisect.bisect_left(tails, x)
        if i == len(tails): tails.append(x)
        else: tails[i] = x
    return len(tails)

random.seed(2)
a = [random.randint(1, 1000) for _ in range(12)]
print("ví dụ:", a, "-> LIS =", lis_n2(a), "/", lis_nlogn(a))
print(f"{'n':>7} | {'O(n^2) (ms)':>12} {'O(n log n) (ms)':>16} | LIS")
for n in (500, 2000, 8000):
    a = [random.randint(1, 10**9) for _ in range(n)]
    t = time.perf_counter(); r1 = lis_n2(a); t1 = time.perf_counter() - t
    t = time.perf_counter(); r2 = lis_nlogn(a); t2 = time.perf_counter() - t
    assert r1 == r2
    print(f"{n:>7} | {t1*1000:>12.1f} {t2*1000:>16.2f} | {r1}")

print()
sys.setrecursionlimit(100000)
def lcs_len_table(a, b):
    prev = [0] * (len(b) + 1)                     # chỉ giữ hai hàng: O(min(m,n)) bộ nhớ
    for x in a:
        cur = [0]
        for j, y in enumerate(b, 1):
            cur.append(prev[j-1] + 1 if x == y else max(prev[j], cur[j-1]))
        prev = cur
    return prev[-1]
def lcs_len_memo(a, b):
    @lru_cache(None)
    def f(i, j):
        if i == len(a) or j == len(b): return 0
        return 1 + f(i + 1, j + 1) if a[i] == b[j] else max(f(i + 1, j), f(i, j + 1))
    return f(0, 0)
print(f"{'độ dài':>7} | {'bảng 2 hàng (ms)':>17} {'memo lru_cache (ms)':>20} | LCS")
random.seed(3)
for n in (200, 500, 900):
    a = "".join(random.choice("ACGT") for _ in range(n)); b = "".join(random.choice("ACGT") for _ in range(n))
    t = time.perf_counter(); r1 = lcs_len_table(a, b); t1 = time.perf_counter() - t
    try:
        t = time.perf_counter(); r2 = lcs_len_memo(a, b); t2 = time.perf_counter() - t
        assert r1 == r2
        print(f"{n:>7} | {t1*1000:>17.1f} {t2*1000:>20.1f} | {r1}")
    except RecursionError:
        print(f"{n:>7} | {t1*1000:>17.1f} {'RecursionError':>20} | {r1}")
```

## Trong hệ thống thật

- **`diff` và `git diff`**: tìm dãy thay đổi ít nhất giữa hai file là bài toán gần LCS trên các dòng; Git mặc định dùng thuật toán của Myers (1986), `O(ND)` với `D` là số khác biệt, nhanh khi hai file giống nhau nhiều.
- **Sửa lỗi chính tả, tìm mờ (fuzzy search)**: edit distance và các biến thể (Damerau-Levenshtein, khoảng cách Jaro-Winkler) nằm trong bộ gợi ý "có phải bạn muốn gõ...", trong công cụ tìm kiếm file và trong căn chỉnh chuỗi DNA (Needleman-Wunsch và Smith-Waterman là LCS và edit distance có trọng số).
- **Định tuyến và đồ thị**: Bellman-Ford (xem [Graph](/docs/dsa/graphs)) và Floyd-Warshall (đường đi ngắn nhất giữa mọi cặp đỉnh) là DP trên đồ thị; đường dài nhất trong DAG, như đường tới hạn của roadmap trong bài Graph, cũng là DP trên thứ tự topo.
- **Xử lý ngôn ngữ và nhận dạng giọng nói**: thuật toán Viterbi tìm chuỗi trạng thái ẩn có xác suất cao nhất là DP.
- **Chia dòng văn bản**: thuật toán Knuth-Plass của TeX chọn chỗ ngắt dòng làm tổng "độ xấu" nhỏ nhất bằng DP.
- **Trình biên dịch**: chọn lệnh máy tối ưu cho cây biểu thức (instruction selection) và phân bổ thanh ghi dùng các kỹ thuật DP.

## Quan sát và chẩn đoán

- **Đếm số trạng thái trước khi cài**: nếu số trạng thái nhân chi phí mỗi trạng thái vượt chừng `10^8`, cần giảm chiều hoặc đổi cách nhìn; DP không phép màu hoá bài toán mũ có quá nhiều trạng thái.
- **Kiểm tra bằng đệ quy thuần trên đầu vào nhỏ** (như phần đổi tiền): so kết quả DP với brute force trên `amount` nhỏ để chắc công thức đúng trước khi tin vào bảng.
- **Truy vết sai** thường do quên lưu lựa chọn hoặc lần ngược theo thứ tự ưu tiên khác với lúc điền; kiểm tra bằng cách tính lại giá trị của lời giải truy vết ra.

| Triệu chứng | Nguyên nhân hay gặp | Cách xử lý |
|---|---|---|
| `RecursionError` với đầu vào lớn | top-down đệ quy sâu | chuyển sang bottom-up |
| Chạy mãi dù đã thêm memo | trạng thái bị khoá bằng tham số thừa (thêm chiều không cần) | định nghĩa lại trạng thái cho gọn |
| Đáp án sai ở cạnh biên | cơ sở sai, hoặc `∞ + 1` bị coi như hợp lệ | kiểm tra ô cơ sở và xử lý "không khả thi" |
| Hết bộ nhớ với bảng hai chiều lớn | `O(mn)` ô | chỉ giữ hai hàng, hoặc dùng Hirschberg nếu cần truy vết |
| Knapsack chạy quá chậm | `W` quá lớn, thuật toán giả đa thức | giảm độ chính xác của `W`, hoặc đổi sang cách xấp xỉ |
| Tham lam chạy nhanh nhưng sai trên một số ca | thiếu tính chất lựa chọn tham lam | dùng DP, hoặc chứng minh bằng lập luận hoán đổi |

## Lưu ý

- Điều quan trọng nhất là **định nghĩa trạng thái** bằng một câu rõ ràng. Hầu hết lỗi DP là trạng thái mơ hồ hoặc thiếu thông tin cần cho lựa chọn kế tiếp.
- DP chỉ có ích khi có **bài con chồng lấp**. Nếu các bài con không trùng nhau (merge sort), chia để trị là đủ và không cần bảng.
- Đệ quy thuần cho bài DP thường là mũ; thêm memo biến nó thành đa thức. Độ phức tạp là **số trạng thái nhân chi phí mỗi trạng thái**.
- Top-down viết nhanh và chỉ tính bài con cần; bottom-up nhanh hơn, không chạm giới hạn đệ quy, và dễ tối ưu bộ nhớ. Với trạng thái sâu, chọn bottom-up.
- Knapsack 0/1 một hàng phải duyệt `w` **giảm dần**; duyệt tăng dần là một bài toán khác (mỗi món lấy được nhiều lần).
- `O(nW)` của knapsack là giả đa thức: đa thức theo **giá trị** của `W`, không phải theo độ dài biểu diễn. Bài toán vẫn NP-hard.
- Tham lam đúng với một số bài (xếp lịch, Huffman, MST) và sai với nhiều bài khác (đổi tiền với hệ bất kỳ). Không chắc thì dùng DP hoặc chứng minh bằng lập luận hoán đổi.
- Sau khi có lời giải DP, hỏi tiếp "có cấu trúc nào cho phép bỏ một chiều của bảng không": LIS `O(n²)` thành `O(n log n)` là ví dụ.
- Lấy giá trị tối ưu và lấy cả lời giải là hai việc khác nhau: truy vết cần lưu lựa chọn hoặc giữ cả bảng.
