## Ý chính

Chuỗi là kiểu dữ liệu phổ biến nhất: tên, địa chỉ, URL, log, mã nguồn, JSON. Trông như một mảng ký tự, nhưng hai điều khiến nó **không** đơn giản như mảng số: (1) "ký tự" là khái niệm mơ hồ (byte, code point hay thứ người nhìn thấy?), và (2) thao tác điển hình không phải truy cập theo chỉ số mà là **tìm** một chuỗi trong chuỗi khác, nên chi phí phụ thuộc vào thuật toán chứ không chỉ vào cấu trúc.

Bài này đi từ dưới lên. Đầu tiên là chuỗi **thực sự là gì** trong bộ nhớ với Unicode tiếng Việt, vì lỗi ở tầng này làm hỏng mọi thứ phía trên (tìm không thấy chữ trông y hệt, đảo ngược làm mất dấu). Sau đó là bốn thuật toán **tìm chuỗi con** tự cài, đếm số phép so sánh trên ba loại dữ liệu và đo thời gian; **suffix array**, chỉ mục cho trường hợp một văn bản và rất nhiều truy vấn; và cuối cùng **regex**, nơi cùng một cú pháp cho hai thuật toán khác nhau một trời một vực: backtracking (mũ) và NFA (tuyến tính), với một ví dụ ReDoS đo được. Code Python 3.13 chạy thật. Bài dùng [bảng băm](/docs/dsa/hash-tables) (Rabin-Karp), [cây và trie](/docs/dsa/trees), [sắp xếp](/docs/dsa/sorting) và [độ phức tạp](/docs/dsa/complexity).

## Chuỗi là gì

Có ba tầng khác nhau cùng gọi là "độ dài":

- **Byte**: dữ liệu thô sau khi **mã hoá** (UTF-8 là mã hoá phổ biến nhất: ký tự ASCII 1 byte, chữ có dấu tiếng Việt 2 đến 3 byte, emoji 4 byte).
- **Code point** (điểm mã): một số trong bảng Unicode (`U+1EC7`). Python `len(s)` đếm code point.
- **Grapheme cluster**: thứ người đọc thấy là **một ký tự**, có thể gồm nhiều code point.

```python
# Chuỗi không phải mảng ký tự: byte, code point và "ký tự người nhìn thấy" là ba thứ khác nhau.
import unicodedata as ud

def show(label, s):
    print(f"{label:<22} {s!r:<24} len (code point) = {len(s):>2}   UTF-8 = {len(s.encode('utf-8')):>2} byte   UTF-16 = {len(s.encode('utf-16-le')) // 2:>2} đơn vị")

print("--- cùng một chữ nhìn y hệt, hai cách biểu diễn khác nhau ---")
nfc = ud.normalize("NFC", "Việt")
nfd = ud.normalize("NFD", "Việt")
show("NFC (dựng sẵn)", nfc); show("NFD (tách dấu)", nfd)
print(f"   nfc == nfd ? {nfc == nfd}    (nhìn giống hệt trên màn hình, nhưng so sánh bằng False)")
print("   code point của 'ệ' dựng sẵn :", [f"U+{ord(c):04X} {ud.name(c)}" for c in "ệ"])
print("   code point của 'ệ' tách dấu :", [f"U+{ord(c):04X} {ud.name(c)}" for c in ud.normalize("NFD", "ệ")])
print(f"   sau chuẩn hoá về NFC cả hai: {ud.normalize('NFC', nfd) == nfc}")

print()
print("--- hậu quả với cấu trúc dữ liệu ---")
d = {nfc: "dòng 1"}
print(f"   dict[{nfd!r}] -> ", d.get(nfd, "KHÔNG TÌM THẤY (băm khác nhau vì byte khác nhau)"))
print(f"   đảo ngược chuỗi NFD làm mất dấu: {nfd[::-1]!r} (dấu tách rời bị gắn vào ký tự sai)")
print(f"   cắt 4 ký tự đầu: NFC {nfc[:3]!r}  NFD {nfd[:3]!r}  (cắt giữa chữ và dấu)")

print()
print("--- đếm gì: byte, code point, hay ký tự hiển thị? ---")
for label, s in (("ASCII", "Hanoi"), ("tiếng Việt NFC", "Hà Nội"), ("tiếng Việt NFD", ud.normalize("NFD", "Hà Nội")),
                 ("cờ Việt Nam", "\U0001F1FB\U0001F1F3"), ("gia đình (ZWJ)", "\U0001F468‍\U0001F469‍\U0001F467")):
    show(label, s)
print("   (cờ = hai ký hiệu vùng; 'gia đình' = ba emoji nối bằng hai ký tự ZWJ ẩn; thứ người nhìn thấy là MỘT ký tự)")

print()
print("--- sắp xếp và so sánh không phân biệt hoa thường ---")
words = ["Đà Nẵng", "Hà Nội", "An Giang", "Cần Thơ", "Huế", "đà lạt"]
print("   sorted() theo code point :", sorted(words))
print("   'Đ' (U+0110) đứng sau 'Z' trong bảng mã nên 'Đà Nẵng' bị xếp sau 'Huế'; 'đà lạt' (chữ thường) còn xếp xa hơn")
print(f"   'ß'.upper() = {'ß'.upper()!r} (một ký tự thành hai); 'ǆ'.title() = {'ǆ'.title()!r}; 'İ'.lower() = {'İ'.lower()!r} (len {len('İ'.lower())})")
print(f"   so sánh không phân biệt hoa thường nên dùng casefold: 'STRASSE'.casefold() == 'straße'.casefold() -> {'STRASSE'.casefold() == 'straße'.casefold()}")

print()
print("--- bộ nhớ của str trong CPython (PEP 393): mỗi ký tự 1, 2 hoặc 4 byte tuỳ code point lớn nhất trong chuỗi ---")
import sys
for label, ch in (("ASCII", "a"), ("Latin-1 (é)", "é"), ("tiếng Việt dựng sẵn (ệ)", "ệ"), ("emoji ngoài BMP", "😀")):
    t = ch * 1000
    print(f"   1000 ký tự '{label}': getsizeof = {sys.getsizeof(t):>5} byte  ({(sys.getsizeof(t) - sys.getsizeof('')) / 1000:.0f} byte mỗi ký tự)")
mixed = "a" * 999 + "😀"
print(f"   999 chữ 'a' + MỘT emoji            : getsizeof = {sys.getsizeof(mixed):>5} byte  (cả chuỗi bị nới lên 4 byte mỗi ký tự vì một ký tự)")
```

Mấy điểm cần thuộc:

1. **Cùng một chữ, hai biểu diễn.** "Việt" có thể viết bằng 4 code point **dựng sẵn** (NFC: `ệ` là một code point `U+1EC7`) hoặc 6 code point **tách dấu** (NFD: `e` cộng dấu chấm dưới `U+0323` cộng dấu mũ `U+0302`). Hiển thị y hệt, nhưng `nfc == nfd` là `False`: byte khác nhau. Dữ liệu tiếng Việt từ nguồn khác nhau (bàn phím, copy từ PDF, hệ điều hành macOS lưu tên file dạng NFD) trộn cả hai dạng thường xuyên.
2. **Hậu quả**: `dict` tìm `nfd` trong khoá `nfc` thất bại vì băm khác nhau; đảo ngược `nfd` ra `'ṭ̂eiV'` (dấu gắn nhầm vào ký tự bên cạnh); cắt 3 ký tự đầu của NFD ra `'Vie'` (mất `ệ` vì dấu bị tách). **Quy tắc**: chuẩn hoá về một dạng (thường NFC, qua `unicodedata.normalize`) ngay khi dữ liệu vào hệ thống, trước khi so sánh, băm, lưu hay đánh chỉ mục.
3. **Đếm**: `Hà Nội` là 6 code point ở NFC (9 byte UTF-8) nhưng 9 code point ở NFD (12 byte). Cờ Việt Nam `🇻🇳` là **hai** code point (hai ký hiệu vùng "V" và "N"). Emoji gia đình là **năm** code point (ba emoji nối bằng hai ký tự nối vô hình ZWJ), 18 byte UTF-8, nhưng **một** ký tự hiển thị. Giới hạn "độ dài tối đa 20 ký tự" cho tên người dùng cần định nghĩa rõ đơn vị (thường là grapheme cluster, theo UAX #29).
4. **Sắp xếp theo code point không đúng thứ tự từ điển**: `sorted()` cho `['An Giang', 'Cần Thơ', 'Huế', 'Hà Nội', 'Đà Nẵng', 'đà lạt']`: "Huế" đứng **trước** "Hà Nội" (vì `u` là `U+0075` nhỏ hơn `à` là `U+00E0`), và chữ `Đ` (`U+0110`) đứng sau cả bảng chữ cái Latin. Thứ tự đúng theo ngôn ngữ cần **collation** (ICU, hoặc `COLLATE "vi_VN.utf8"` trong PostgreSQL). Và so sánh không phân biệt hoa thường phải dùng `casefold()`, không phải `lower()` (`'ß'.upper()` thành `'SS'`, `'İ'.lower()` thành hai code point).
5. **Bộ nhớ của `str` trong CPython** (PEP 393) dùng **1, 2 hoặc 4 byte mỗi ký tự** tuỳ code point **lớn nhất** trong chuỗi: 1.000 chữ ASCII chiếm 1.041 byte, 1.000 chữ `ệ` chiếm 2.058 byte, 1.000 emoji chiếm 4.060 byte. Chỉ **một** emoji trong 999 chữ `a` kéo cả chuỗi lên 4.060 byte. Truy cập `s[i]` luôn `O(1)` theo **code point**, một lợi ích của việc dùng độ rộng cố định trong cùng một chuỗi; các ngôn ngữ dùng UTF-8 thẳng (Go, Rust) lập chỉ mục theo **byte** và `O(1)`, nhưng chỉ số có thể rơi giữa một ký tự nhiều byte.

## Tìm chuỗi con

Bài toán: cho văn bản `T` dài `n` và mẫu `P` dài `m`, tìm mọi vị trí `P` xuất hiện trong `T`. Cách ngây thơ (**naive**): thử từng vị trí, so sánh ký tự từng ký tự, lệch thì dịch một bước và làm lại từ đầu. Tốn `O(n·m)` trong trường hợp xấu. Ba cải tiến mỗi cái giải một khía cạnh:

- **KMP** (Knuth-Morris-Pratt): khi lệch, **không dịch mẫu ngây thơ** mà dùng thông tin "phần đã khớp có tiền tố nào cũng là hậu tố", nhảy mẫu tới vị trí thông minh, và **con trỏ trên văn bản không bao giờ lùi**. Cần bảng thất bại tính trước từ mẫu trong `O(m)`. Tổng `O(n + m)` trong **mọi** trường hợp.
- **Rabin-Karp**: so **mã băm** của cửa sổ văn bản với mã băm của mẫu thay vì so ký tự; mã băm của cửa sổ kế tiếp tính trong `O(1)` từ cửa sổ trước (**băm lăn**, rolling hash). Khớp băm mới kiểm tra thật để loại va chạm. `O(n + m)` kỳ vọng; mạnh ở chỗ **mở rộng được ra nhiều mẫu cùng lúc** (một tập băm của mọi mẫu) và 2D.
- **Horspool** (đơn giản hoá của Boyer-Moore): so ký tự **từ cuối mẫu**; khi lệch, nhìn ký tự cuối của cửa sổ văn bản và **nhảy** theo bảng "ký tự này cách cuối mẫu bao xa", có thể nhảy cả độ dài mẫu. Trường hợp tốt `O(n/m)`: **bỏ qua phần lớn văn bản**.

Dưới đây là cả bốn, đếm số phép so sánh, kiểm tra cùng cho một danh sách vị trí, và đo thời gian trên ba loại văn bản; cuối cùng so với `str.find` có sẵn:

```python
# Tìm chuỗi con: naive, KMP, Rabin-Karp (băm lăn) và Horspool. Đếm số lần so sánh ký tự (hoặc phép tính băm) và đo thời gian.
import random, time

def naive(t, p):
    cmp, res = 0, []
    for i in range(len(t) - len(p) + 1):
        j = 0
        while j < len(p):
            cmp += 1
            if t[i + j] != p[j]: break
            j += 1
        if j == len(p): res.append(i)
    return res, cmp

def failure(p):
    """f[i] = độ dài tiền tố dài nhất của p[:i+1] cũng là hậu tố (không tính chính nó)."""
    f, k = [0] * len(p), 0
    for i in range(1, len(p)):
        while k and p[i] != p[k]: k = f[k - 1]
        if p[i] == p[k]: k += 1
        f[i] = k
    return f

def kmp(t, p):
    f, cmp, res, k = failure(p), 0, [], 0
    for i, c in enumerate(t):
        while k:
            cmp += 1
            if c == p[k]: break
            k = f[k - 1]                           # lùi trong MẪU, con trỏ trên văn bản không bao giờ lùi
        else:
            cmp += 1
        if c == p[k]: k += 1
        if k == len(p): res.append(i - k + 1); k = f[k - 1]
    return res, cmp

def rabin_karp(t, p, base=256, mod=1_000_003):
    m, n = len(p), len(t)
    if m > n: return [], 0
    hp = ht = 0; high = pow(base, m - 1, mod); ops, res, collisions = 0, [], 0
    for i in range(m): hp = (hp * base + ord(p[i])) % mod; ht = (ht * base + ord(t[i])) % mod
    for i in range(n - m + 1):
        ops += 1
        if hp == ht:
            if t[i:i + m] == p: res.append(i)
            else: collisions += 1                  # băm trùng nhưng chuỗi khác: phải kiểm tra thật và loại
        if i < n - m: ht = ((ht - ord(t[i]) * high) * base + ord(t[i + m])) % mod      # cập nhật băm trong O(1)
    return res, ops, collisions

def horspool(t, p):
    m, shift, cmp, res = len(p), {}, 0, []
    for i in range(m - 1): shift[p[i]] = m - 1 - i
    i = 0
    while i <= len(t) - m:
        j = m - 1
        while j >= 0:
            cmp += 1
            if t[i + j] != p[j]: break
            j -= 1
        if j < 0: res.append(i)
        i += shift.get(t[i + m - 1], m)            # nhảy theo ký tự cuối cửa sổ: có thể nhảy cả độ dài mẫu
    return res, cmp

print("bảng thất bại của KMP cho mẫu 'ABABCABAB' (tính tay: tiền tố cũng là hậu tố dài nhất ở mỗi vị trí):")
p = "ABABCABAB"
print("   ký tự :", "  ".join(p))
print("   f[i]  :", "  ".join(str(x) for x in failure(p)))

random.seed(1)

Rabin-Karp đáng nhắc riêng vì **băm lăn** là một kỹ thuật dùng ở nhiều nơi khác: công cụ đồng bộ file `rsync` dùng băm lăn để tìm khối trùng giữa hai phiên bản của một file, và các hệ thống sao lưu và loại bỏ trùng lặp dùng nó để **cắt dữ liệu thành khối theo nội dung** (content-defined chunking), chống việc chèn một byte ở đầu file làm đổi mọi khối.

## Suffix array: một văn bản, rất nhiều truy vấn

Mọi thuật toán trên đều **quét văn bản** cho mỗi truy vấn: `O(n)` mỗi lần. Nếu văn bản **cố định** và truy vấn **rất nhiều** (genome 3 tỉ ký tự, kho mã nguồn, từ điển), ta muốn **xây chỉ mục một lần** rồi trả lời mỗi truy vấn không phụ thuộc `n`. **Suffix array** là mảng chứa các chỉ số bắt đầu của mọi **hậu tố** của `T`, **sắp xếp theo thứ tự từ điển**. Mọi hậu tố bắt đầu bằng mẫu `P` nằm **liền nhau** trong mảng đã sắp xếp, nên tìm hai đầu bằng **tìm nhị phân** trong `O(m log n)`.

Cách xây trực tiếp (sắp xếp các hậu tố) tốn `O(n² log n)`. Bản dưới dùng **nhân đôi tiền tố** (prefix doubling): xếp hạng hậu tố theo 1 ký tự đầu, rồi 2, 4, 8... và mỗi vòng dùng hạng của vòng trước để so sánh cặp, tổng `O(n log² n)`. Thêm **mảng LCP** (độ dài tiền tố chung của hai hậu tố liền kề trong mảng) tính bằng thuật toán Kasai trong `O(n)`, giúp tìm chuỗi lặp dài nhất, so sánh hai hậu tố bất kỳ...

```python
# Chỉ mục trên chuỗi: suffix array (xây bằng nhân đôi tiền tố), tìm mọi vị trí của một mẫu bằng tìm nhị phân, mảng LCP.
import random, time, bisect

def suffix_array(s):
    """Prefix doubling: xếp hạng các hậu tố theo 1, 2, 4, 8... ký tự đầu, O(n log^2 n)."""
    n = len(s); sa = list(range(n)); rank = [ord(c) for c in s]; k = 1
    while True:
        key = lambda i: (rank[i], rank[i + k] if i + k < n else -1)
        sa.sort(key=key)
        new = [0] * n
        for a in range(1, n): new[sa[a]] = new[sa[a - 1]] + (key(sa[a]) != key(sa[a - 1]))
        rank = new
        if rank[sa[-1]] == n - 1: break
        k *= 2
    return sa

def lcp_array(s, sa):
    """Kasai: lcp[i] = độ dài tiền tố chung của hậu tố sa[i] và sa[i-1], tính trong O(n)."""
    n = len(s); rank = [0] * n
    for i, p in enumerate(sa): rank[p] = i
    lcp, h = [0] * n, 0
    for i in range(n):
        if rank[i] > 0:
            j = sa[rank[i] - 1]
            while i + h < n and j + h < n and s[i + h] == s[j + h]: h += 1
            lcp[rank[i]] = h
            if h: h -= 1
        else: h = 0
    return lcp

def search(s, sa, p):
    """Mọi vị trí của p: các hậu tố bắt đầu bằng p nằm liền nhau trong mảng; tìm nhị phân hai đầu."""
    lo = bisect.bisect_left(sa, p, key=lambda i: s[i:i + len(p)])
    hi = bisect.bisect_right(sa, p, key=lambda i: s[i:i + len(p)])
    return sorted(sa[lo:hi])

s = "banana"
sa = suffix_array(s)
print(f"văn bản {s!r}: các hậu tố theo thứ tự từ điển")
lcp = lcp_array(s, sa)
for i, p in enumerate(sa): print(f"   sa[{i}] = {p}   {s[p:]:<8} lcp = {lcp[i]}")

    out, i = [], t.find(p)
    while i != -1: out.append(i); i = t.find(p, i + 1)
    return out

print(f"   suffix array: xây một lần {t_build * 1000:7.0f} ms, rồi 2.000 truy vấn {t_sa * 1000:7.0f} ms ({t_sa / 2000 * 1e6:6.0f} µs mỗi truy vấn)")

Cái giá: bộ nhớ (một số nguyên cho mỗi ký tự văn bản, thường gấp 4 đến 8 lần văn bản) và văn bản phải **cố định** (đổi văn bản là xây lại). Biến thể tiết kiệm bộ nhớ hơn là **FM-index** (dựa trên biến đổi Burrows-Wheeler, nén được tới gần kích thước nén của văn bản) mà các công cụ gióng hàng DNA như BWA và Bowtie dùng để tìm hàng triệu đoạn đọc trong bộ gen người. **Suffix tree** làm cùng việc ở dạng cây (xây trong `O(n)` bằng thuật toán Ukkonen, nhưng tốn bộ nhớ hơn nhiều).

Họ hàng gần là **trie** ([Tree](/docs/dsa/trees)): trie của tập từ trả lời "từ nào bắt đầu bằng tiền tố này"; suffix array là cách rút gọn của trie của **mọi hậu tố**. Còn khi cần tìm **nhiều mẫu cùng lúc** trong một dòng văn bản (lọc từ khoá cấm, quét virus), thuật toán **Aho-Corasick** biến trie thành một automat chạy trên văn bản một lần trong `O(n + tổng độ dài mẫu + số kết quả)`.

## Regex: hai thuật toán sau một cú pháp

Regex (biểu thức chính quy) mô tả một **tập chuỗi**; câu hỏi "chuỗi này có khớp không" có hai cách giải rất khác nhau.

**Backtracking** (Perl, Python `re`, Java, JavaScript, PCRE): duyệt regex như một chương trình, mỗi khi gặp lựa chọn (`|`, `*`) thì thử một nhánh, **thất bại thì quay lui** thử nhánh khác. Dễ hiểu, hỗ trợ tính năng mạnh (tham chiếu ngược `\1`, lookahead), nhưng với regex có lựa chọn **lồng nhau** thì số nhánh phải thử tăng **theo cấp số mũ**.

**NFA** (Thompson, 1968; RE2, Rust `regex`, Go `regexp`, `grep` cổ điển): dựng **automat hữu hạn không tất định** từ regex, rồi chạy với **tập trạng thái đang sống**: mỗi ký tự của văn bản làm tập đó chuyển sang tập mới, không bao giờ quay lui. Thời gian `O(|regex| × |văn bản|)`, **tuyến tính trong mọi trường hợp**, đổi lại không hỗ trợ tham chiếu ngược (bài toán này NP-khó).

Dưới đây là bộ dựng NFA kiểu Thompson (hỗ trợ ký tự, `.`, `|`, `*`, `+`, `?`, ngoặc) cùng bộ mô phỏng tập trạng thái, so với `re` của Python trên regex `(a+)+b` với văn bản toàn chữ `a` (không bao giờ khớp, vì không có `b`):

```python
# Regex hai kiểu: backtracking (như module re của Python) và mô phỏng NFA kiểu Thompson (không bao giờ quay lui).
# Hỗ trợ: ký tự thường, '.', '|', '*', '+', '?', ngoặc ( ).
import re, time

# ---- phân tích cú pháp thành cây, rồi dựng NFA bằng cấu trúc Thompson ----
class Frag:
    def __init__(self, start, outs): self.start, self.outs = start, outs     # outs: danh sách (state, ô) cần nối tới đích

class NFA:
    def __init__(self): self.t = []                                           # t[i] = ('char', c, next) | ('split', a, b) | ('match',)
    def add(self, s): self.t.append(list(s)); return len(self.t) - 1
    def patch(self, outs, target):
        for st, slot in outs: self.t[st][slot] = target

def compile_regex(pat):
    nfa, pos = NFA(), [0]
    def peek(): return pat[pos[0]] if pos[0] < len(pat) else None
    def eat(): c = pat[pos[0]]; pos[0] += 1; return c
    def alt():
        f = seq()
        while peek() == '|':
            eat(); g = seq(); s = nfa.add(('split', f.start, g.start)); f = Frag(s, f.outs + g.outs)
        return f
    def seq():
        frags = []
        while peek() not in (None, '|', ')'): frags.append(rep())
        if not frags: s = nfa.add(('split', None, None)); return Frag(s, [(s, 1), (s, 2)])     # chuỗi rỗng
        f = frags[0]
        for g in frags[1:]: nfa.patch(f.outs, g.start); f = Frag(f.start, g.outs)
        return f
    def rep():
        f = atom()
        while peek() in ('*', '+', '?'):
            op = eat()
            if op == '*': s = nfa.add(('split', f.start, None)); nfa.patch(f.outs, s); f = Frag(s, [(s, 2)])
            elif op == '+': s = nfa.add(('split', f.start, None)); nfa.patch(f.outs, s); f = Frag(f.start, [(s, 2)])
            else: s = nfa.add(('split', f.start, None)); f = Frag(s, f.outs + [(s, 2)])
        return f
    def atom():
        c = eat()
        if c == '(': f = alt(); eat(); return f                             # nuốt ')'
        s = nfa.add(('char', c, None)); return Frag(s, [(s, 2)])
    f = alt()
    m = nfa.add(('match',)); nfa.patch(f.outs, m)
    return nfa, f.start

def nfa_match(nfa, start, text):
    """Giữ TẬP các trạng thái đang sống; mỗi ký tự chỉ duyệt tập đó một lần: O(|regex| x |text|), không quay lui."""
    def closure(states):
        seen, stack = set(), list(states)
        while stack:
            s = stack.pop()
            if s in seen: continue
            seen.add(s)
            if nfa.t[s][0] == 'split': stack += [x for x in nfa.t[s][1:3] if x is not None]
        return seen
    cur = closure([start]); peak = len(cur)
    for ch in text:
        nxt = [s[2] for i in cur for s in [nfa.t[i]] if s[0] == 'char' and (s[1] == ch or s[1] == '.')]
        cur = closure(nxt); peak = max(peak, len(cur))
        if not cur: return False, peak
    return any(nfa.t[i][0] == 'match' for i in cur), peak

nfa, start = compile_regex("(a|b)*abb")
print("regex (a|b)*abb:", {w: nfa_match(nfa, start, w)[0] for w in ("abb", "aabb", "babb", "ab", "abba")})
for pat, tests in (("a(b|c)*d", ["ad", "abcbd", "abx"]), ("(ab)+c?", ["ab", "ababc", "abb"]), ("h.llo", ["hello", "hallo", "hllo"])):
    c, s = compile_regex(pat)
    assert all(nfa_match(c, s, w)[0] == bool(re.fullmatch(pat, w)) for w in tests)
print("NFA khớp với module re trên 3 regex nữa và 9 xâu thử: đúng")

print()
print("ReDoS: regex (a+)+b trên 'aaaa...a' (không có 'b'), cho tới khi thất bại:")
print(f"{'n':>4} {'re (backtracking)':>20} {'NFA (Thompson)':>16} {'trạng thái sống tối đa':>24}")
pat = "(a+)+b"
c, s = compile_regex(pat)
prev = None
for n in (16, 18, 20, 22, 24, 26):

    t0 = time.perf_counter(); re.match(pat, text); t_re = time.perf_counter() - t0

Đầu tiên là kiểm tra đúng đắn: NFA khớp đúng như module `re` trên bốn regex và 14 xâu thử. Rồi bảng **ReDoS** (regular expression denial of service): với regex `(a+)+b` trên `a` lặp `n` lần, `re` tốn 1,7 ms ở `n = 16`, **1.802 ms ở `n = 26`**; **mỗi lần thêm 2 ký tự thời gian nhân 4** (tức nhân đôi mỗi ký tự thêm), đường cong mũ điển hình. Ngoại suy cùng đường cong tới `n = 40` (thêm 14 ký tự, nhân 2^14) thì mất khoảng 1,8 s × 16.384 ≈ **8 giờ**. Còn NFA: 0,02 đến 0,05 ms, **tăng tuyến tính**, và tập trạng thái sống chỉ có **4** ở mọi `n`.

Vấn đề không nằm ở `n` lớn mà ở việc **kẻ tấn công chọn được đầu vào**: một chuỗi 30 ký tự có thể giữ một luồng CPU hàng phút. Hai sự cố nổi tiếng: **Stack Overflow** (tháng 7 năm 2016) ngừng hoạt động vì một regex xử lý khoảng trắng gặp một bài đăng có hàng nghìn khoảng trắng; **Cloudflare** (2 tháng 7 năm 2019) làm CPU toàn bộ mạng lưới chạm 100% do một quy tắc WAF có regex backtracking, gây sự cố toàn cầu. Cách phòng:

- Dùng engine **bảo đảm thời gian tuyến tính** (RE2, Rust `regex`, Go `regexp`) cho đầu vào không tin cậy.
- Với engine backtracking: tránh **lặp lồng nhau** (`(a+)+`, `(a|aa)+`, `(.*)*`), đặt giới hạn thời gian và độ dài đầu vào, dùng **lặp chiếm hữu** (possessive) hoặc nhóm nguyên tử nếu engine hỗ trợ (Java, PCRE, `re` của Python từ 3.11 có `(?>...)` và `a++`).
- Đừng dùng regex cho thứ phân tích cú pháp được bằng parser (HTML, email đầy đủ, JSON): chúng vừa dễ sai vừa dễ dính ReDoS.

## Trong hệ thống thật

- **`grep` và `ripgrep`**: dùng automat hữu hạn (không backtracking, trừ khi bạn dùng PCRE); `ripgrep` dựng lên trên crate `regex` của Rust, kết hợp **SIMD** để tìm các byte đặc trưng của mẫu (một biến thể của ý tưởng nhảy kiểu Horspool) trước khi chạy automat.
- **Thư viện chuẩn**: `str.find` của Python và `String.indexOf` của Java, `strstr` của glibc đều dùng thuật toán tinh chỉnh (glibc cho mẫu dài dùng Two-Way); đừng tự viết trừ khi có lý do.
- **Cơ sở dữ liệu**: `LIKE '%abc%'` không dùng được chỉ mục B-tree (xem [Indexing](/docs/databases/indexing)); giải pháp là chỉ mục **trigram** (`pg_trgm`, cắt văn bản thành mọi ba ký tự liền nhau và lập chỉ mục ngược, chính là ý tưởng "băm cửa sổ" của Rabin-Karp đưa vào chỉ mục GIN) hoặc tìm kiếm toàn văn (Elasticsearch, PostgreSQL `tsvector`: chỉ mục ngược theo **từ**, chứ không theo vị trí ký tự).
- **Bộ gen**: BWA, Bowtie dùng FM-index trên bộ gen người (3 tỉ ký tự) để gióng hàng hàng triệu đoạn đọc ngắn trong vài giờ.
- **Chuỗi trong bộ nhớ**: nhiều runtime **intern** chuỗi (dùng chung một bản cho các chuỗi giống nhau: tên biến, khoá JSON lặp lại), dựa vào băm ([Hash Table](/docs/dsa/hash-tables)); Java 9+ lưu chuỗi Latin-1 bằng 1 byte mỗi ký tự tương tự PEP 393 của Python.

## Quan sát và chẩn đoán

- Python: `len(s)`, `len(s.encode())`, `unicodedata.normalize('NFC', s)`, `unicodedata.name(c)` để biết đang đếm gì. Để đếm grapheme cần thư viện (`regex` với `\X`, `grapheme`) vì thư viện chuẩn không có.
- So sánh hai chuỗi nhìn y hệt mà `==` sai: in `[hex(ord(c)) for c in s]` cả hai.
- Với regex nghi chậm: thử với đầu vào xấu cố ý (lặp ký tự rồi đổi ký tự cuối) và đo thời gian khi tăng `n` từng bước nhỏ; nếu thời gian **nhân lên** theo `n` là có vấn đề; công cụ `regex101` hiển thị số bước backtrack, và có công cụ phân tích tĩnh phát hiện mẫu nguy hiểm.

| Triệu chứng | Nguyên nhân hay gặp | Cách xử lý |
|---|---|---|
| Tìm hoặc so sánh không thấy chữ trông y hệt | NFC so với NFD (hoặc hai biến thể Unicode khác) | chuẩn hoá về NFC khi nhập dữ liệu và khi so sánh |
| Cắt hoặc đảo chuỗi làm hỏng dấu, emoji | thao tác theo code point cắt giữa một grapheme | thao tác theo grapheme cluster |
| Giới hạn độ dài trường nhập báo sai | đếm byte hay code point thay vì ký tự hiển thị | chọn đơn vị đúng cho từng ràng buộc |
| Thứ tự sắp xếp tên tiếng Việt sai | sắp theo code point | collation theo ngôn ngữ (ICU, `COLLATE`) |
| CPU kẹt 100% khi gặp một đầu vào lạ | regex backtracking gặp đầu vào xấu | engine tuyến tính (RE2), giới hạn thời gian, bỏ lặp lồng nhau |
| Tìm chuỗi con trên văn bản lớn lặp lại rất chậm | quét lại cả văn bản mỗi truy vấn | chỉ mục (suffix array, trigram, chỉ mục ngược) |
| `LIKE '%x%'` quét cả bảng | B-tree không hỗ trợ tìm giữa chuỗi | chỉ mục trigram hoặc tìm kiếm toàn văn |

## Lưu ý

- "Độ dài chuỗi" có ít nhất ba nghĩa (byte, code point, grapheme cluster); luôn nói rõ đơn vị. Tiếng Việt và emoji làm ba con số khác nhau.
- Chuẩn hoá Unicode (NFC) **trước** khi so sánh, băm, lưu hay đánh chỉ mục; hai chuỗi nhìn giống hệt có thể khác nhau byte.
- Sắp xếp theo code point không đúng thứ tự từ điển của ngôn ngữ; dùng collation. So sánh không phân biệt hoa thường dùng `casefold`.
- Naive tìm chuỗi con có thể `O(n·m)`; KMP bảo đảm `O(n + m)`, Horspool thường nhảy qua phần lớn văn bản, Rabin-Karp mạnh khi nhiều mẫu. Trong thực tế dùng hàm có sẵn của thư viện.
- Băm lăn tính hash của cửa sổ kế tiếp trong `O(1)`; nó là nền của `rsync` và của cắt khối theo nội dung.
- Suffix array đổi `O(n)` mỗi truy vấn lấy `O(m log n)`, với chi phí xây một lần và bộ nhớ lớn; chỉ có lợi khi văn bản cố định và truy vấn nhiều.
- Regex backtracking có thể chậm theo **cấp số mũ** trên đầu vào xấu (ReDoS); với đầu vào không tin cậy dùng engine tuyến tính, và tránh lặp lồng nhau.
- Đừng dùng regex để phân tích cú pháp ngôn ngữ lồng nhau (HTML, JSON); dùng parser.
- `LIKE '%x%'` trong cơ sở dữ liệu không dùng được chỉ mục thường; cần trigram hoặc tìm kiếm toàn văn.
