## Ý chính

Mảng cho tra cứu theo chỉ số nhanh; bảng băm cho tra cứu theo khoá nhanh nhưng **không có thứ tự**: không hỏi được "khoá nhỏ nhất", "khoá ngay sau `k`", "mọi khoá trong khoảng `[a, b]`". Mảng đã sắp xếp có thứ tự nhưng chèn vào giữa tốn `O(n)`. <Term>Tree</Term> giải bài toán này bằng cách tổ chức dữ liệu thành cây: mỗi lần so sánh loại bỏ một nhánh, nên nếu cây **thấp** thì tìm, chèn, xoá, tìm khoảng đều tốn `O(log n)` và thứ tự được giữ nguyên.

Chữ "nếu cây thấp" là toàn bộ câu chuyện của bài. Một cây tìm kiếm nhị phân chèn theo thứ tự sai sẽ thoái hoá thành danh sách liên kết (`O(n)`). Các cấu trúc phía sau đều là cách giữ chiều cao thấp: **phép xoay** (AVL, red-black), **rộng ra thay vì cao lên** (B-tree), hoặc **bỏ yêu cầu thứ tự toàn phần để đổi lấy cấu trúc đơn giản hơn** (heap). Cuối bài là trie, cây theo ký tự của khoá thay vì theo so sánh.

Bài đi theo trình tự: cây nhị phân và các kiểu duyệt; BST tự cài, đo chiều cao khi chèn ngẫu nhiên và khi chèn tăng dần; AVL và red-black với phép xoay có kiểm chứng bất biến; heap và việc xây heap trong `O(n)`; B-tree và B+ tree, nền của chỉ mục cơ sở dữ liệu; trie. Mọi code là Python 3.13 chạy thật. Bài này cần [Array & Linked List](/docs/dsa/arrays-linked-lists) và [Big-O & Complexity](/docs/dsa/complexity), và là nền cho [Graph](/docs/dsa/graphs) cũng như chỉ mục B-tree của chặng cơ sở dữ liệu.

## Cây nhị phân và các kiểu duyệt

Một cây là tập các **nút** nối với nhau thành phân cấp: một nút **gốc**, mỗi nút có con (có thể không có), không có vòng. Ở **cây nhị phân** mỗi nút có tối đa hai con, gọi là con trái và con phải. Vài từ cần thống nhất:

- **Độ sâu** của nút: số cạnh từ gốc tới nó (gốc có độ sâu 0). **Chiều cao** của cây: số tầng (bài này đếm số nút trên đường dài nhất từ gốc tới lá, nên cây một nút có chiều cao 1).
- **Lá**: nút không có con.
- Cây nhị phân có `n` nút thì chiều cao nhỏ nhất là `⌈log2(n+1)⌉` (cây đầy) và lớn nhất là `n` (cây thành một đường thẳng).

Một cấu trúc có hai con trỏ như vậy cho bốn cách đi qua mọi nút, gọi là **duyệt**. Ba cách đầu đệ quy (chỉ khác thời điểm "thăm" nút so với hai nhánh), cách thứ tư dùng hàng đợi:

| Kiểu duyệt | Thứ tự | Dùng để |
|---|---|---|
| preorder | nút, trái, phải | sao chép cây, ghi cây ra file (gốc đi trước) |
| inorder | trái, nút, phải | với BST cho ra dãy khoá **tăng dần** |
| postorder | trái, phải, nút | xoá cây, tính kích thước (con xong trước cha) |
| levelorder | từng tầng, trái sang phải | duyệt theo BFS (xem [Graph](/docs/dsa/graphs)) |

## Cây tìm kiếm nhị phân (BST)

<Term>Binary search tree</Term> thêm một quy tắc vào cây nhị phân: với **mọi** nút, các khoá ở cây con trái đều **nhỏ hơn** khoá của nút, các khoá ở cây con phải đều **lớn hơn**. Hệ quả: tìm một khoá bắt đầu ở gốc, mỗi bước so sánh rồi rẽ trái hoặc phải, bỏ cả một nhánh. Duyệt inorder cho dãy đã sắp xếp.

Dưới đây là BST tự cài: `insert` và `find` bằng vòng lặp (để cây lệch không làm tràn stack đệ quy), `delete` xử lý ba trường hợp, bốn kiểu duyệt, và hàm in cây xoay 90 độ (con phải ở trên, con trái ở dưới).

```python
import random, sys
from collections import deque
sys.setrecursionlimit(10000)

class Node:
    __slots__ = ("key", "left", "right")
    def __init__(self, key): self.key, self.left, self.right = key, None, None

class BST:
    def __init__(self): self.root, self.n = None, 0
    def insert(self, key):                       # vòng lặp: không sợ tràn stack khi cây lệch
        if self.root is None: self.root = Node(key); self.n = 1; return 1
        cur, steps = self.root, 1
        while True:
            steps += 1
            if key == cur.key: return steps
            side = "left" if key < cur.key else "right"
            nxt = getattr(cur, side)
            if nxt is None:
                setattr(cur, side, Node(key)); self.n += 1; return steps
            cur = nxt
    def find(self, key):
        cur = self.root
        while cur and cur.key != key:
            cur = cur.left if key < cur.key else cur.right
        return cur
    def delete(self, key):
        self.root = self._delete(self.root, key)
    def _delete(self, node, key):
        if node is None: return None
        if key < node.key: node.left = self._delete(node.left, key)
        elif key > node.key: node.right = self._delete(node.right, key)
        else:
            self.n -= 1
            if node.left is None: return node.right          # 0 hoặc 1 con (phải)
            if node.right is None: return node.left          # 1 con (trái)
            succ = node.right                                 # 2 con: lấy kế nhiệm (nhỏ nhất bên phải)
            while succ.left: succ = succ.left
            node.key = succ.key
            self.n += 1                                       # _delete bên dưới sẽ trừ lại 1
            node.right = self._delete(node.right, succ.key)
        return node
    # bốn kiểu duyệt
    def inorder(self, n=None, first=True):
        n = self.root if first else n
        if n: yield from self.inorder(n.left, False); yield n.key; yield from self.inorder(n.right, False)
    def preorder(self, n=None, first=True):
        n = self.root if first else n
        if n: yield n.key; yield from self.preorder(n.left, False); yield from self.preorder(n.right, False)
    def postorder(self, n=None, first=True):
        n = self.root if first else n
        if n: yield from self.postorder(n.left, False); yield from self.postorder(n.right, False); yield n.key
    def levelorder(self):
        q = deque([self.root] if self.root else [])
        while q:
            n = q.popleft(); yield n.key
            if n.left: q.append(n.left)
            if n.right: q.append(n.right)
    def height(self):                                         # vòng lặp theo tầng
        h, level = 0, [self.root] if self.root else []
        while level:
            h += 1
            level = [c for n in level for c in (n.left, n.right) if c]
        return h

def show(node, prefix="", is_left=None):
    if node is None: return
    if node.right: show(node.right, prefix + ("│   " if is_left else "    "), False)
    print(prefix + ("└── " if is_left else "┌── " if is_left is False else "") + str(node.key))
    if node.left: show(node.left, prefix + ("    " if is_left is not False else "│   "), True)

t = BST()
for k in (50, 30, 70, 20, 40, 60, 80, 35):
    t.insert(k)
show(t.root)
print("inorder   :", list(t.inorder()), "(luôn tăng dần)")
print("preorder  :", list(t.preorder()))
print("postorder :", list(t.postorder()))
print("levelorder:", list(t.levelorder()))
t.delete(20);  print("xoá 20 (lá)        ->", list(t.levelorder()))
t.delete(30);  print("xoá 30 (1 con)     ->", list(t.levelorder()))
t.delete(50);  print("xoá 50 (2 con, gốc)->", list(t.levelorder()), "| n =", t.n)
```

```text
    ┌── 70
    │   └── 60
50
    │   ┌── 40
    │   │   └── 35
    └── 30
        └── 20
inorder   : [20, 30, 35, 40, 50, 60, 70, 80] (luôn tăng dần)
preorder  : [50, 30, 20, 40, 35, 70, 60, 80]
postorder : [20, 35, 40, 30, 60, 80, 70, 50]
levelorder: [50, 30, 70, 20, 40, 60, 80, 35]
xoá 20 (lá)        -> [50, 30, 70, 40, 60, 80, 35]
```

Đọc hình: gốc 50, nhánh phải (80, 70, 60) ở trên, nhánh trái (40, 35, 30, 20) ở dưới. Ba trường hợp xoá:

- **Xoá lá** (20): chỉ cần cắt nó.
- **Xoá nút một con** (30, lúc này chỉ còn con 40 sau khi 20 đã mất): nối con của nó lên thế chỗ.
- **Xoá nút hai con** (gốc 50): không thể cắt, vì sẽ mất cả hai cây con. Thay khoá của nó bằng khoá **kế nhiệm** (nhỏ nhất của cây con phải, ở đây là 60, nút trái nhất đi từ con phải), rồi xoá nút kế nhiệm đó, mà theo định nghĩa nó không có con trái nên rơi về hai trường hợp đầu. Có thể dùng **tiền nhiệm** (lớn nhất của cây con trái) với cùng hiệu quả.

### BST phụ thuộc thứ tự chèn

Mọi thao tác của BST đi theo một đường từ gốc xuống, nên chi phí tỉ lệ với **chiều cao**, và chiều cao lại phụ thuộc vào thứ tự chèn. Chèn các khoá ngẫu nhiên thì cây "nặng bụng" tự nhiên; chèn các khoá đã sắp xếp thì mỗi khoá mới đi sang phải mãi, cây thành một đường thẳng. Đo:

```python
import random, math
random.seed(2)
print(f"{'n':>7} | {'chèn ngẫu nhiên: cao':>21} {'2·log2 n':>9} | {'chèn đã sắp xếp: cao':>22} | {'tìm TB (ngẫu nhiên)':>20}")
for n in (1_000, 10_000, 100_000):
    keys = random.sample(range(10 * n), n)
    a = BST(); total = sum(a.insert(k) for k in keys)
    b = BST()
    for k in sorted(keys[:min(n, 4000)]): b.insert(k)           # 4000 để khỏi chờ lâu
    print(f"{n:>7} | {a.height():>21} {2*math.log2(n):>9.1f} | {b.height():>13} (n={min(n,4000)}) | {total/n:>20.2f}")
```

```text
      n |  chèn ngẫu nhiên: cao  2·log2 n |  chèn đã sắp xếp: cao |  tìm TB (ngẫu nhiên)
   1000 |                    22      19.9 |          1000 (n=1000) |                12.58
  10000 |                    31      26.6 |          4000 (n=4000) |                16.03
 100000 |                    42      33.2 |          4000 (n=4000) |                21.41
```

Chèn ngẫu nhiên giữ cây ở chiều cao cỡ `2 đến 3 · log2 n` (22, 31, 42 tầng cho 1.000, 10.000, 100.000 khoá), và một lần chèn thăm trung bình 12 đến 21 nút. Chèn đã sắp xếp cho chiều cao **bằng đúng `n`**: BST thoái hoá thành danh sách liên kết, và mỗi thao tác là `O(n)`. Đó không phải trường hợp hiếm: dữ liệu thật hay đã sắp sẵn (ID tăng dần, dấu thời gian, tên theo thứ tự chữ cái). Mọi cấu trúc dưới đây tồn tại để loại bỏ hiểm hoạ này.

## Tự cân bằng bằng phép xoay: AVL

**Phép xoay** là thao tác cục bộ đổi hình dạng cây mà **giữ nguyên thứ tự inorder**: con trỏ của hai nút được đảo, `O(1)`.

```text
xoay phải tại y             xoay trái tại x
      y            x             x               y
     / \          / \           / \             / \
    x   C   ->   A   y         A   y     ->    x   C
   / \              / \           / \         / \
  A   B            B   C         B   C       A   B
```

Cả hai phía của hình đều giữ A, B, C theo đúng thứ tự trái sang phải, nên là cùng một BST hợp lệ; chỉ khác chiều cao: xoay phải kéo `x` lên, đưa cây trái xuống một tầng cho cây phải.

**AVL** (Adelson-Velsky và Landis, 1962) là cây tự cân bằng đầu tiên. Bất biến: tại **mọi** nút, chiều cao hai cây con lệch nhau **tối đa 1**. Sau mỗi lần chèn hoặc xoá, đi ngược lên từ chỗ thay đổi, tính lại chiều cao, và nếu một nút bị lệch 2 thì sửa bằng một hoặc hai phép xoay. Có bốn trường hợp:

| Trường hợp | Hình dạng | Cách sửa |
|---|---|---|
| LL | lệch trái, con trái cũng lệch trái (hoặc cân bằng) | một phép xoay phải |
| RR | đối xứng | một phép xoay trái |
| LR | lệch trái, nhưng con trái lệch phải | xoay trái ở con trái, rồi xoay phải |
| RL | đối xứng | xoay phải ở con phải, rồi xoay trái |

```python
import random, math, sys
sys.setrecursionlimit(10000)

class N:
    __slots__ = ("key", "left", "right", "h")
    def __init__(self, key): self.key, self.left, self.right, self.h = key, None, None, 1

def h(n): return n.h if n else 0
def upd(n): n.h = 1 + max(h(n.left), h(n.right))
def bal(n): return h(n.left) - h(n.right)

rotations = {"LL": 0, "RR": 0, "LR": 0, "RL": 0}

def rot_right(y):
    x = y.left
    y.left, x.right = x.right, y
    upd(y); upd(x)
    return x
def rot_left(x):
    y = x.right
    x.right, y.left = y.left, x
    upd(x); upd(y)
    return y

def rebalance(n):
    upd(n)
    b = bal(n)
    if b > 1:                                   # lệch trái
        if bal(n.left) < 0: n.left = rot_left(n.left); rotations["LR"] += 1
        else: rotations["LL"] += 1
        return rot_right(n)
    if b < -1:                                  # lệch phải
        if bal(n.right) > 0: n.right = rot_right(n.right); rotations["RL"] += 1
        else: rotations["RR"] += 1
        return rot_left(n)
    return n

def insert(n, key):
    if n is None: return N(key)
    if key < n.key: n.left = insert(n.left, key)
    elif key > n.key: n.right = insert(n.right, key)
    else: return n
    return rebalance(n)

def delete(n, key):
    if n is None: return None
    if key < n.key: n.left = delete(n.left, key)
    elif key > n.key: n.right = delete(n.right, key)
    else:
        if n.left is None: return n.right
        if n.right is None: return n.left
        s = n.right
        while s.left: s = s.left
        n.key = s.key
        n.right = delete(n.right, s.key)
    return rebalance(n)

def check(n):                                   # kiểm tra bất biến AVL và thứ tự BST
    if n is None: return 0, math.inf, -math.inf
    hl, lo_l, hi_l = check(n.left); hr, lo_r, hi_r = check(n.right)
    assert abs(hl - hr) <= 1, "lệch quá 1"
    assert hi_l < n.key < lo_r, "sai thứ tự BST"
    return 1 + max(hl, hr), min(lo_l, n.key), max(hi_r, n.key)

def levels(root):
    out, cur = [], [root]
    while any(cur):
        out.append([x.key if x else "·" for x in cur])
        cur = [c for x in cur if x for c in (x.left, x.right)]
        if all(c is None for c in cur): break
    return out

print("chèn 10, 20, 30 vào BST thường sẽ thành một đường thẳng; AVL xoay:")
root = None
for k in (10, 20, 30):
    root = insert(root, k)
print("  các tầng:", levels(root), "| xoay:", {k: v for k, v in rotations.items() if v})
for k in rotations: rotations[k] = 0
root = None
for k in (30, 10, 20):
    root = insert(root, k)
print("chèn 30, 10, 20 (lệch trái-phải, cần xoay đôi):", levels(root), "| xoay:", {k: v for k, v in rotations.items() if v})

print()
print(f"{'n':>8} | {'chèn tăng dần: cao':>19} {'1.44·log2(n+2)':>15} | {'chèn ngẫu nhiên: cao':>21} | {'số lần xoay / n':>16}")
for n in (1_000, 10_000, 100_000):
    for k in rotations: rotations[k] = 0
    root = None
    for k in range(n): root = insert(root, k)
    check(root); h_sorted = h(root); rot = sum(rotations.values())
    random.seed(4); keys = random.sample(range(10 * n), n); r2 = None
    for k in keys: r2 = insert(r2, k)
    check(r2)
    print(f"{n:>8} | {h_sorted:>19} {1.44 * math.log2(n + 2):>15.1f} | {h(r2):>21} | {rot / n:>16.2f}")

# xoá một nửa số khoá, vẫn cân bằng
for k in keys[: n // 2]: r2 = delete(r2, k)
check(r2)
print(f"sau khi xoá một nửa ({n // 2} khoá còn lại): vẫn hợp lệ AVL, chiều cao = {h(r2)}")
```

```text
sau khi xoá một nửa (50000 khoá còn lại): vẫn hợp lệ AVL, chiều cao = 19
```

Ví dụ nhỏ hai dòng đầu minh hoạ hai trường hợp: chèn 10, 20, 30 làm cây lệch phải ba tầng nên một phép xoay trái (RR) kéo 20 lên gốc; chèn 30, 10, 20 tạo ra hình gấp khúc (30 có con trái 10, 10 có con phải 20) nên cần xoay đôi (LR), và cả hai cùng cho cây cân bằng `[20] / [10, 30]`.

Bảng thứ hai là phần quan trọng: `check` chạy xác nhận bất biến AVL và thứ tự BST còn đúng sau mọi chèn và xoá, và chiều cao nằm sát đáy lý thuyết: chèn **tăng dần** 100.000 khoá cho chiều cao **17** (so với `n = 100000` của BST thường), trong khi cận lý thuyết của AVL là `1,44·log2(n+2)` = 23,9. Mỗi lần chèn tăng dần tốn khoảng một phép xoay. Xoá một nửa số khoá, cây vẫn là AVL hợp lệ.

## Red-black tree

AVL giữ cây rất cân bằng nên tìm nhanh, nhưng cái giá là phải cập nhật chiều cao và xoay nhiều khi xoá. **Red-black tree** nới lỏng cân bằng để sửa ít hơn: mỗi nút có một bit màu đỏ hoặc đen, thoả các luật

1. gốc đen; nút đỏ không có con đỏ;
2. mọi đường từ một nút xuống các lá (rỗng) của nó đều đi qua **cùng số nút đen** (chiều cao đen).

Hai luật này cho cận chiều cao `≤ 2·log2(n+1)`: đường dài nhất xen kẽ đỏ-đen và không dài hơn **gấp đôi** đường ngắn nhất (toàn đen). Cây cao hơn AVL một chút (cận 2 so với 1,44) nhưng mỗi lần chèn hay xoá cần tối đa vài phép xoay và đổi màu.

Cách dễ hiểu nhất là xem red-black như một **2-3-4 tree** (mỗi nút giữ 1 tới 3 khoá) mã hoá bằng nhị phân: một nút 3 hoặc 4 của 2-3-4 là các nút đen với con đỏ nối liền. Biến thể **left-leaning red-black** (LLRB, Sedgewick) thêm luật "liên kết đỏ luôn nghiêng trái", giúp phép chèn chỉ còn ba dòng sửa:

```python
import math, random, sys
sys.setrecursionlimit(10000)
RED, BLACK = True, False

class N:
    __slots__ = ("key", "left", "right", "color")
    def __init__(self, key, color): self.key, self.left, self.right, self.color = key, None, None, color

def is_red(n): return n is not None and n.color == RED
def rotate_left(h):
    x = h.right; h.right, x.left = x.left, h
    x.color, h.color = h.color, RED
    return x
def rotate_right(h):
    x = h.left; h.left, x.right = x.right, h
    x.color, h.color = h.color, RED
    return x
def flip(h):                      # nút có hai con đỏ ~ nút 4 trong 2-3-4 tree: tách, đẩy màu đỏ lên
    h.color = RED; h.left.color = BLACK; h.right.color = BLACK

def insert(h, key):
    if h is None: return N(key, RED)
    if key < h.key: h.left = insert(h.left, key)
    elif key > h.key: h.right = insert(h.right, key)
    if is_red(h.right) and not is_red(h.left): h = rotate_left(h)
    if is_red(h.left) and is_red(h.left.left): h = rotate_right(h)
    if is_red(h.left) and is_red(h.right): flip(h)
    return h

def check(h):                     # trả về (chiều cao đen, chiều cao thật)
    if h is None: return 1, 0
    assert not (is_red(h) and (is_red(h.left) or is_red(h.right))), "đỏ có con đỏ"
    assert not is_red(h.right), "đỏ nghiêng phải"
    bl, hl = check(h.left); br, hr = check(h.right)
    assert bl == br, "chiều cao đen khác nhau"
    return bl + (0 if is_red(h) else 1), 1 + max(hl, hr)

print(f"{'n':>8} | {'chèn tăng dần: cao':>19} {'cận 2·log2(n+1)':>16} | {'chèn ngẫu nhiên: cao':>21} | {'chiều cao đen':>14}")
for n in (1_000, 10_000, 100_000):
    root = None
    for k in range(n):
        root = insert(root, k); root.color = BLACK
    bh, ht = check(root)
    random.seed(9); r2 = None
    for k in random.sample(range(10 * n), n):
        r2 = insert(r2, k); r2.color = BLACK
    bh2, ht2 = check(r2)
    print(f"{n:>8} | {ht:>19} {2 * math.log2(n + 1):>16.1f} | {ht2:>21} | {bh:>6} / {bh2:<5}")
```

```text
       n |  chèn tăng dần: cao  cận 2·log2(n+1) |  chèn ngẫu nhiên: cao |  chiều cao đen
    1000 |                  10             19.9 |                    13 |     10 / 9    
   10000 |                  14             26.6 |                    19 |     14 / 12   
  100000 |                  17             33.2 |                    23 |     17 / 15
```

Ba lệnh `if` trong `insert` chính là toàn bộ logic cân bằng, và `check` xác nhận cả ba luật sau mỗi lần chèn. Chèn tăng dần 100.000 khoá cho chiều cao 17 (sát log2 n ≈ 16,6), chèn ngẫu nhiên 23; cả hai đều rất xa cận 33,2. Chiều cao đen bằng `10, 14, 17` cho thấy khi chèn tăng dần, cây gần như chỉ gồm nút đen. Bản xoá của LLRB dài hơn nên bài không cài; các cài đặt thực tế (như trong C++ STL, Java và kernel Linux) dùng red-black tổng quát với các thao tác xoá được chứng minh kỹ.

### AVL hay red-black

| | AVL | Red-black |
|---|---|---|
| Cận chiều cao | `~1,44 log2 n` | `~2 log2 n` |
| Tìm kiếm | nhanh hơn một chút (cây thấp hơn) | hơi chậm hơn |
| Chèn, xoá | nhiều xoay hơn, mỗi lần đi ngược lên cập nhật chiều cao | tối đa vài xoay, đổi màu |
| Dùng khi | đọc nhiều, ghi ít | đọc và ghi lẫn lộn (lựa chọn mặc định của thư viện chuẩn) |

Cả hai đều `O(log n)` cho mọi thao tác. Trong thực tế khác biệt hiệu năng nhỏ, và đa số thư viện chọn red-black.

Ghi chú trung thực về đo đạc: Python thuần mỗi thao tác bị chi phí thông dịch lấn át, nên bài này đo **chiều cao và số xoay**, không đo thời gian.

## Heap và priority queue

Một số bài toán không cần toàn bộ thứ tự, chỉ cần **phần tử nhỏ nhất ngay lúc này**: scheduler chọn task có hạn chót sớm nhất, Dijkstra chọn đỉnh gần nhất, trộn `k` danh sách đã sắp xếp, "top k" của một dòng dữ liệu. <Term>Priority queue</Term> là giao diện cho yêu cầu đó: `push(x)` và `pop()` lấy phần tử nhỏ nhất. <Term>Heap</Term> nhị phân là cách cài thường dùng.

Heap nhị phân (min-heap) là cây nhị phân **đầy tới tầng áp chót** (tầng cuối điền từ trái) thoả **tính chất heap**: khoá của mỗi nút `≤` khoá của hai con. Không có thứ tự giữa hai anh em hay giữa các tầng, nên nó "lỏng" hơn BST: chỉ gốc là nhỏ nhất.

Vì cây luôn "đầy từ trái", ta không cần con trỏ: lưu thẳng vào một **mảng**, nút `i` có cha ở `(i-1) // 2` và hai con ở `2i+1` và `2i+2`. Đây là lần nữa mảng thắng con trỏ (xem [Array & Linked List](/docs/dsa/arrays-linked-lists)): heap liền khối, thân thiện cache, không tốn bộ nhớ cho con trỏ.

- **`push`**: thêm vào cuối mảng, rồi **sift-up**: đổi chỗ với cha chừng nào còn nhỏ hơn cha. Cây cao `log2 n` nên tối đa `log2 n` bước.
- **`pop`**: lấy gốc, đưa phần tử cuối lên gốc, rồi **sift-down**: đổi chỗ với con **nhỏ hơn** chừng nào còn lớn hơn nó. Tối đa `log2 n` bước.

```python
import random, heapq, math

class MinHeap:
    def __init__(self): self.a, self.cmp = [], 0
    def push(self, x):
        a = self.a; a.append(x); i = len(a) - 1
        while i > 0:                              # sift-up
            p = (i - 1) // 2; self.cmp += 1
            if a[p] <= a[i]: break
            a[p], a[i] = a[i], a[p]; i = p
    def pop(self):
        a = self.a; top = a[0]; last = a.pop()
        if a:
            a[0] = last; i, n = 0, len(a)
            while True:                           # sift-down
                l, r, m = 2 * i + 1, 2 * i + 2, i
                if l < n:
                    self.cmp += 1
                    if a[l] < a[m]: m = l
                if r < n:
                    self.cmp += 1
                    if a[r] < a[m]: m = r
                if m == i: break
                a[i], a[m] = a[m], a[i]; i = m
        return top
    @classmethod
    def heapify(cls, items):                      # xây từ dưới lên: O(n)
        h = cls(); h.a = list(items); n = len(h.a)
        for start in range(n // 2 - 1, -1, -1):
            i = start
            while True:
                l, r, m = 2 * i + 1, 2 * i + 2, i
                if l < n:
                    h.cmp += 1
                    if h.a[l] < h.a[m]: m = l
                if r < n:
                    h.cmp += 1
                    if h.a[r] < h.a[m]: m = r
                if m == i: break
                h.a[i], h.a[m] = h.a[m], h.a[i]; i = m
        return h

random.seed(8)
h = MinHeap()
for x in (5, 3, 8, 1, 9, 2, 7): h.push(x)
print("sau khi push 5,3,8,1,9,2,7 mảng heap =", h.a)
print("pop lần lượt:", [h.pop() for _ in range(7)])

print()
print(f"{'n':>8} | {'push n lần: so sánh':>20} | {'heapify: so sánh':>17} {'2n':>9} | {'n log2 n':>10}")
for n in (1_000, 10_000, 100_000, 1_000_000):
    data = [random.random() for _ in range(n)]
    a = MinHeap()
    for x in data: a.push(x)
    b = MinHeap.heapify(data)
    assert b.a[0] == min(data)
    print(f"{n:>8} | {a.cmp:>20} | {b.cmp:>17} {2*n:>9} | {n * math.log2(n):>10.0f}")

data = [random.random() for _ in range(200_000)]
h = MinHeap.heapify(data); out = [h.pop() for _ in range(len(data))]
assert out == sorted(data)
```

```text
pop lần lượt: [1, 2, 3, 5, 7, 8, 9]

       n |  push n lần: so sánh |  heapify: so sánh        2n |   n log2 n
    1000 |                 2216 |              1858      2000 |       9966
   10000 |                22641 |             18791     20000 |     132877
  100000 |                227726 |            187774    200000 |    1660964

```

Mảng `[1, 3, 2, 5, 9, 8, 7]` là heap: gốc 1; hai con của nó (vị trí 1 và 2) là 3 và 2; hai con của 3 (vị trí 3 và 4) là 5 và 9, hai con của 2 (vị trí 5 và 6) là 8 và 7. Mọi nút nhỏ hơn con của nó; `pop` 7 lần cho ra dãy tăng dần (đó là **heapsort**: `n` lần `pop` tốn `O(n log n)`, kèm bài kiểm tra cuối đoạn code trên với 200.000 số).

### Xây heap trong O(n)

Hai cách đưa `n` phần tử vào heap. Cách một: `push` từng phần tử, `n log n` trong trường hợp xấu nhất. Cách hai: bỏ cả mảng vào rồi **heapify** (sift-down từ nút cha cuối cùng ngược về gốc). Bảng trên cho thấy heapify tốn **dưới `2n`** so sánh (1858, 18791, 187774, 1880963; xấp xỉ `1,88n`) trong khi `n log2 n` là 9966 đến 19,9 triệu: tuyến tính thật chứ không phải `n log n`.

Vì sao `O(n)`? Phần lớn nút ở gần đáy, nơi sift-down chạy rất ít bước. Một nửa số nút là lá (0 bước), một phần tư cách lá một tầng (tối đa 1 bước), một phần tám cách hai tầng (tối đa 2 bước), v.v. Tổng số bước tối đa là

```text
n/4 * 1 + n/8 * 2 + n/16 * 3 + ...  =  n * (1/4 + 2/8 + 3/16 + ...)  =  n * sum(k / 2^(k+1))  <  n
```

vì chuỗi `sum k/2^k = 2`. Mỗi bước tốn hai so sánh nên tổng `< 2n`, khớp số đo. (Còn `push` từng phần tử trên dữ liệu **ngẫu nhiên** thực ra cũng chỉ tốn khoảng `2,28n` so sánh, vì phần tử mới thường dừng sớm; cận `n log n` chỉ xảy ra với dữ liệu đưa vào theo thứ tự giảm dần.)

Python có sẵn `heapq` (min-heap trên `list`, API `heappush`, `heappop`, `heapify`, `nsmallest`); với max-heap thì đổi dấu khoá. Heapsort và các ứng dụng khác của heap được dùng lại ở [Sorting](/docs/dsa/sorting) và [Graph](/docs/dsa/graphs).

## B-tree và B+ tree: cây cho dữ liệu trên đĩa

BST và AVL giữ cây cân bằng nhưng mỗi nút chỉ có một khoá và hai con. Với `n = 10^9`, cây thấp nhất cũng 30 tầng, và mỗi tầng là một lần nhảy tới một vùng nhớ khác (một cache miss, hoặc tệ hơn một lần đọc đĩa). Trên đĩa, chi phí được đo bằng **số trang phải đọc** chứ không phải số phép so sánh: đọc một trang 4 KB tốn gần như bằng đọc một byte (xem [File Systems](/docs/os/file-systems) và [I/O Devices](/docs/os/io-devices)). Vậy hãy làm mỗi nút **vừa đúng một trang**, chứa hàng trăm khoá.

<Term>B-tree</Term> (Bayer và McCreight, 1972) làm đúng thế. Bậc `t`: mỗi nút (trừ gốc) có từ `t-1` đến `2t-1` khoá, nút trong có số con bằng số khoá cộng một, khoá trong nút được sắp xếp và chia khoảng cho các cây con, và **mọi lá nằm cùng độ sâu** (cây luôn cân bằng hoàn hảo). Tìm khoá: trong mỗi nút tìm nhị phân vị trí rồi đi xuống con tương ứng; mỗi nút là một lần đọc trang.

Chèn: đi xuống tới lá và chèn. Nếu nút đã đầy (`2t-1` khoá), **tách** nó làm hai nút `t-1` khoá và đẩy khoá giữa lên cha. Nếu cha cũng đầy, tách tiếp lên trên; chỉ khi gốc bị tách thì cây **cao thêm một tầng**. Cây không bao giờ mất cân bằng vì chỉ lớn lên ở gốc, mọi lá luôn cùng độ sâu.

```python
import random, math, bisect

class BNode:
    def __init__(self, leaf): self.keys, self.kids, self.leaf = [], [], leaf

class BTree:
    def __init__(self, t):
        self.t = t; self.root = BNode(True); self.reads = 0
    def search(self, key):
        n = self.root
        while True:
            self.reads += 1                           # mỗi nút = một trang đĩa
            i = bisect.bisect_left(n.keys, key)
            if i < len(n.keys) and n.keys[i] == key: return True
            if n.leaf: return False
            n = n.kids[i]
    def insert(self, key):
        r = self.root
        if len(r.keys) == 2 * self.t - 1:             # gốc đầy: tách, cây cao thêm 1
            s = BNode(False); s.kids = [r]; self.root = s
            self._split(s, 0); r = s
        self._insert_nonfull(r, key)
    def _split(self, parent, i):
        t = self.t; y = parent.kids[i]; z = BNode(y.leaf)
        mid = y.keys[t - 1]
        z.keys, y.keys = y.keys[t:], y.keys[:t - 1]
        if not y.leaf: z.kids, y.kids = y.kids[t:], y.kids[:t]
        parent.keys.insert(i, mid); parent.kids.insert(i + 1, z)
    def _insert_nonfull(self, n, key):
        while True:
            i = bisect.bisect_left(n.keys, key)
            if i < len(n.keys) and n.keys[i] == key: return
            if n.leaf: n.keys.insert(i, key); return
            if len(n.kids[i].keys) == 2 * self.t - 1:
                self._split(n, i)
                if key > n.keys[i]: i += 1
                elif key == n.keys[i]: return
            n = n.kids[i]
    def height(self):
        h, n = 1, self.root
        while not n.leaf: n = n.kids[0]; h += 1
        return h
    def count(self, n=None):
        n = n or self.root
        return 1 + sum(self.count(k) for k in n.kids)
    def check(self, n=None, lo=-math.inf, hi=math.inf, depth=1, leaf_depths=None):
        first = n is None
        n = n or self.root; leaf_depths = leaf_depths if leaf_depths is not None else set()
        assert n.keys == sorted(n.keys) and all(lo < k < hi for k in n.keys)
        if n is not self.root: assert self.t - 1 <= len(n.keys) <= 2 * self.t - 1
        if n.leaf: leaf_depths.add(depth)
        else:
            assert len(n.kids) == len(n.keys) + 1
            b = [lo] + n.keys + [hi]
            for i, k in enumerate(n.kids): self.check(k, b[i], b[i + 1], depth + 1, leaf_depths)
        if first: assert len(leaf_depths) == 1, "mọi lá phải cùng độ sâu"

t = BTree(2)
for k in range(1, 11): t.insert(k)
def dump(n, d=0):
    print("  " * d + str(n.keys))
    for k in n.kids: dump(k, d + 1)
print("B-tree t=2 sau khi chèn 1..10:"); dump(t.root); t.check()

print()
random.seed(6)
N = 200_000
keys = random.sample(range(10 * N), N)
print(f"{'bậc t':>6} {'khoá/nút tối đa':>16} {'chiều cao':>10} {'số nút':>8} {'số trang đọc TB / lần tìm':>26}")
for tt in (2, 8, 64, 256):
    bt = BTree(tt)
    for k in keys: bt.insert(k)
    bt.check()
    bt.reads = 0
    for k in keys[:20_000]: bt.search(k)
    print(f"{tt:>6} {2*tt-1:>16} {bt.height():>10} {bt.count():>8} {bt.reads / 20_000:>26.2f}")
print(f"(so sánh: BST nhị phân cân bằng cho {N:,} khoá cao khoảng {math.ceil(math.log2(N + 1))} tầng)")
```


Ví dụ nhỏ với `t = 2` (mỗi nút 1 đến 3 khoá, tức cây 2-3-4): sau 10 lần chèn tăng dần, gốc `[4]` chia hai nhánh; tất cả lá (`[1]`, `[3]`, `[5]`, `[7]`, `[9, 10]`) nằm cùng độ sâu 3. Bảng sau cho thấy tác dụng của bậc: với 200.000 khoá, bậc `t = 2` cao 14 tầng (tìm tốn 12 trang), nhưng bậc `t = 64` (mỗi nút tối đa 127 khoá) chỉ **3 tầng**, và mỗi lần tìm đọc **trung bình 2,96 trang**, so với gần 18 tầng của cây nhị phân cân bằng. Đây cũng là lý do số nút thu từ 113.857 xuống 2282: nút chứa nhiều khoá nên cần ít nút hơn.

Với trang thực 4 KB, khoá 8 byte cộng con trỏ 8 byte cho khoảng 256 khoá mỗi nút. Tính chiều cao theo `⌈log_fanout(n)⌉` (đã chạy):

| Kích thước khoá + con trỏ | Khoá mỗi trang 4 KB | 10^6 khoá | 10^9 khoá | 10^12 khoá |
|---|---|---|---|---|
| 8 B + 8 B | khoảng 256 | 3 tầng | 4 tầng | 5 tầng |
| 16 B + 8 B | khoảng 170 | 3 tầng | 5 tầng | 6 tầng |
| 64 B + 8 B | khoảng 56 | 4 tầng | 6 tầng | 7 tầng |

Một chỉ mục có **một nghìn tỉ khoá** chỉ cao 5 đến 7 tầng, và vài tầng trên cùng thường nằm sẵn trong bộ nhớ. Vì vậy một lần tra trên bảng khổng lồ chỉ tốn vài lần đọc đĩa. Đó là lý do B-tree (và biến thể) là cấu trúc chỉ mục chuẩn của gần như mọi hệ quản trị cơ sở dữ liệu và file system.

### B+ tree

Hầu hết hệ thống dùng biến thể **B+ tree**: chỉ **lá** mới chứa dữ liệu (hoặc con trỏ tới dòng dữ liệu), các nút trong chỉ chứa khoá dẫn đường. Hai hệ quả:

- Nút trong **không mang dữ liệu** nên nhồi được nhiều khoá dẫn đường hơn trong một trang, fan-out cao hơn, cây thấp hơn.
- Các lá được nối thành **danh sách liên kết**, nên truy vấn khoảng `[a, b]` chỉ cần tìm `a` rồi đi ngang qua các lá, không phải leo lên xuống cây.

Đây là hình dạng của chỉ mục trong PostgreSQL, MySQL InnoDB, SQLite và của cấu trúc thư mục trong nhiều file system (XFS, btrfs, NTFS). Chặng cơ sở dữ liệu sẽ quay lại cấu trúc này để nói về chỉ mục clustered, composite và chi phí ghi.

## Trie

Mọi cây ở trên so sánh **cả khoá** ở mỗi nút. Với khoá là chuỗi, cách khác là đi theo **từng ký tự**: <Term>trie</Term> có mỗi cạnh gắn một ký tự, đường từ gốc tới một nút "kết thúc" là một từ. Tìm một chuỗi dài `m` đi `m` cạnh, `O(m)`, **không phụ thuộc số từ** trong tập, và mọi từ chung tiền tố dùng chung đoạn đường. Ba việc trie làm tự nhiên: kiểm tra có từ nào, liệt kê mọi từ với tiền tố cho trước (autocomplete), và tìm tiền tố **dài nhất** khớp với một chuỗi (cách router chọn route, xem trie cho longest prefix match ở [IP & Routing](/docs/networking/ip-routing)).

Bộ từ để thử là 1.602 tên thuộc tính của một số module chuẩn của Python (không có file từ điển sẵn trên máy viết bài này):

```python
import sys, importlib, builtins, time, bisect

class TrieNode:
    __slots__ = ("kids", "end")
    def __init__(self): self.kids, self.end = {}, False

class Trie:
    def __init__(self): self.root, self.nodes = TrieNode(), 1
    def insert(self, w):
        n = self.root
        for ch in w:
            nxt = n.kids.get(ch)
            if nxt is None: nxt = n.kids[ch] = TrieNode(); self.nodes += 1
            n = nxt
        n.end = True
    def _walk(self, p):
        n = self.root
        for ch in p:
            n = n.kids.get(ch)
            if n is None: return None
        return n
    def contains(self, w):
        n = self._walk(w); return bool(n and n.end)
    def with_prefix(self, p, limit=10**9):
        out, n = [], self._walk(p)
        if n is None: return out
        stack = [(n, p)]
        while stack and len(out) < limit:
            n, s = stack.pop()
            if n.end: out.append(s)
            for ch in sorted(n.kids, reverse=True): stack.append((n.kids[ch], s + ch))
        return out

words = set(dir(builtins))
for m in ("os", "sys", "re", "json", "math", "itertools", "collections", "functools", "socket", "threading", "subprocess", "pathlib", "string", "random", "time", "datetime", "typing", "asyncio", "logging", "http.client"):
    words.update(dir(importlib.import_module(m)))
words = sorted(w for w in words if w.isidentifier())
T = Trie()
for w in words: T.insert(w)

total_chars = sum(len(w) for w in words)
print(f"{len(words)} từ, tổng {total_chars} ký tự; trie có {T.nodes} nút (dùng chung tiền tố tiết kiệm {1 - T.nodes/total_chars:.0%} so với số ký tự)")
for p in ("thread", "os.", "is_", "__ge", "zzz"):
    r = T.with_prefix(p)
    print(f"  tiền tố {p!r:<9}: {len(r):>3} từ  {r[:4]}")
print("contains('threading') =", T.contains("threading"), "| contains('threadin') =", T.contains("threadin"))

def prefix_sorted(p):
    i = bisect.bisect_left(words, p); out = []
    while i < len(words) and words[i].startswith(p): out.append(words[i]); i += 1
    return out
for p in ("thread", "is_", "__ge"):
    assert sorted(T.with_prefix(p)) == prefix_sorted(p)
def t(fn, reps=2000):
    s = time.perf_counter()
    for _ in range(reps): fn()
    return (time.perf_counter() - s) / reps * 1e6
print(f"truy vấn tiền tố 'thread': trie {t(lambda: T.with_prefix('thread')):.1f} µs | mảng sắp xếp + bisect {t(lambda: prefix_sorted('thread')):.1f} µs")
print(f"bộ nhớ đối tượng trie (ước lượng): ~{T.nodes * (sys.getsizeof(TrieNode()) + sys.getsizeof({})) / 2**20:.1f} MB cho {len(words)} từ (mảng chuỗi: ~{(sum(sys.getsizeof(w) for w in words) + 8*len(words)) / 2**20:.2f} MB)")
```

Hai điều trung thực rút ra từ bảng số, không "vẽ" cho đẹp:

- Trie dùng chung tiền tố: 12.120 nút cho 17.737 ký tự (tiết kiệm 32% so với số ký tự). Nhưng nút trie trong Python là object kèm dict, nên **bộ nhớ thực lớn gấp khoảng 14 lần** mảng chuỗi (1,3 MB so với 0,09 MB).
- Với truy vấn tiền tố trên một tập **tĩnh**, **mảng đã sắp xếp cộng `bisect`** nhanh hơn trie khoảng 8 lần (0,5 µs so với 3,9 µs) vì tìm nhị phân trên mảng liền khối và liệt kê các phần tử liền kề.

Vậy trie thắng khi nào? Khi tập từ **thay đổi liên tục** (mảng sắp xếp chèn tốn `O(n)`), khi cần **khớp tiền tố dài nhất** hoặc **đi tới từng ký tự một** (bộ gõ gợi ý khi người dùng gõ, bộ định tuyến), hoặc khi cài đặt tiết kiệm bộ nhớ hơn bằng mảng (không phải dict cho mỗi nút) hoặc nén (radix tree / Patricia trie, nút gộp đường không rẽ nhánh). Nó không phải là lựa chọn mặc định cho "tìm theo tiền tố".

## Trong hệ thống thật

- **Cây tìm kiếm cân bằng trong thư viện chuẩn**: `std::map` và `std::set` của C++ (thường là red-black), `TreeMap` của Java (red-black), `std::collections::BTreeMap` của Rust (B-tree, vì B-tree thân thiện cache hơn cây nhị phân ngay cả trong bộ nhớ). Python chuẩn **không có** cây cân bằng; người ta dùng `bisect` trên list đã sắp xếp hoặc thư viện ngoài như `sortedcontainers` (danh sách các khối, một dạng "B-tree nông").
- **Kernel Linux** dùng red-black tree (`rbtree`) ở nhiều nơi: scheduler CFS giữ các task sắp xếp theo `vruntime` để lấy ngay task đã chạy ít nhất bên trái nhất (xem [CPU Scheduling](/docs/os/cpu-scheduling)), và bộ lập lịch I/O. Các vùng nhớ ảo của process (VMA, xem [Virtual Memory](/docs/os/virtual-memory)) từng nằm trong red-black tree; từ Linux 6.1 chúng chuyển sang một cấu trúc cây khác là maple tree.
- **Cơ sở dữ liệu và file system**: B+ tree cho chỉ mục (PostgreSQL, MySQL InnoDB, SQLite) và cho thư mục trong file system (XFS, btrfs). Xem [File Systems](/docs/os/file-systems).
- **Redis sorted set** dùng **skip list** thay vì cây cân bằng: danh sách liên kết nhiều tầng với "đường cao tốc" chọn ngẫu nhiên, cho `O(log n)` kỳ vọng với cài đặt đơn giản hơn và dễ hơn cho tìm khoảng.
- **Heap**: `heapq` của Python, `priority_queue` của C++, `container/heap` của Go; timer của các runtime (hạn gần nhất ở gốc) và scheduler đều dựa vào heap.

## Quan sát và chẩn đoán

- Đo **chiều cao** và **phân bố độ sâu** của cây của bạn: chiều cao vượt xa `2 log2 n` là dấu hiệu mất cân bằng.
- Với B-tree trong cơ sở dữ liệu, các công cụ riêng cho thấy số trang đã đọc (ví dụ `EXPLAIN (ANALYZE, BUFFERS)` của PostgreSQL ở chặng cơ sở dữ liệu).
- Khi một thao tác trên cấu trúc có thứ tự "tự dưng" chậm, hỏi: dữ liệu vào có sắp sẵn không, và cấu trúc có tự cân bằng không?

| Triệu chứng | Nguyên nhân hay gặp | Cách xử lý |
|---|---|---|
| BST tự cài chậm dần, tràn stack khi đệ quy | dữ liệu đến theo thứ tự, cây thoái hoá thành danh sách | dùng cây tự cân bằng, hoặc xáo trộn đầu vào |
| Chèn dữ liệu tăng dần vào chỉ mục rất chậm hoặc chỉ mục phình to | trang bị tách liên tục, mật độ lá thấp | nạp hàng loạt (bulk load) theo thứ tự rồi mới tạo chỉ mục |
| Tìm khoảng chậm trên cấu trúc băm | bảng băm không có thứ tự | dùng cây cân bằng hoặc B+ tree |
| `pop` của heap trả về thứ không đúng thứ tự mong muốn | tính chất heap chỉ bảo đảm gốc nhỏ nhất, không phải toàn thứ tự | duyệt heap không cho dãy sắp xếp; `pop` lần lượt mới cho |
| Autocomplete tốn quá nhiều RAM | trie dùng dict hoặc object cho mỗi nút | dùng mảng, radix tree, hoặc mảng đã sắp xếp cộng bisect |

## Lưu ý

- Chi phí `O(log n)` của BST chỉ đúng khi cây **thấp**. BST thường không tự cân bằng: chèn dữ liệu đã sắp xếp cho chiều cao bằng `n` và mọi thao tác `O(n)`.
- Phép xoay giữ thứ tự inorder, chỉ đổi hình dạng. AVL cân bằng chặt hơn (đọc nhanh), red-black cân bằng lỏng hơn (ghi ít xoay hơn); cả hai `O(log n)`.
- Heap chỉ cho biết phần tử nhỏ nhất, **không** phải cấu trúc có thứ tự toàn phần. Không thể tìm một khoá bất kỳ trong heap nhanh hơn `O(n)`.
- Xây heap từ mảng bằng `heapify` là `O(n)`, nhanh hơn `push` từng phần tử trong trường hợp xấu nhất.
- Trên đĩa, đơn vị chi phí là **trang đọc**, không phải phép so sánh; vì vậy B-tree chọn fan-out hàng trăm, không phải 2.
- B+ tree đặt dữ liệu ở lá và nối lá thành danh sách để tìm khoảng nhanh; đây là hình dạng của hầu hết chỉ mục thực tế.
- Trie không tự động tốt hơn mảng đã sắp xếp: thắng ở tập thay đổi liên tục và ở khớp tiền tố dài nhất; thua về bộ nhớ nếu cài bằng dict mỗi nút.
- Khoá của mọi cây có thứ tự phải so sánh được và quan hệ thứ tự phải **nhất quán** (quên điều này thì cây hỏng im lặng).
- Duyệt đệ quy một cây cao có thể tràn stack (xem phần space complexity ở [Big-O & Complexity](/docs/dsa/complexity)); dùng vòng lặp hoặc stack tường minh cho cây có thể lệch.
