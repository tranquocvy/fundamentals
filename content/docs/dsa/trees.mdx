## Ý chính

Bảng băm tra theo khoá rất nhanh nhưng không có thứ tự: không hỏi được "khoá nhỏ nhất", "các khoá từ 100 tới 200". Mảng đã sắp xếp thì có thứ tự và tìm nhị phân được, nhưng chèn vào giữa tốn `O(n)`. <Term>Binary search tree</Term> (BST) có cả hai: mỗi nút chia các khoá thành nhỏ hơn (bên trái) và lớn hơn (bên phải), nên mỗi lần so sánh bỏ đi một nhánh, giống tìm nhị phân, mà chèn chỉ là gắn thêm một nút.

Mọi thao tác của BST đi theo một đường từ gốc xuống, nên chi phí bằng **chiều cao** của cây. Cây thấp thì `O(log n)`; cây lệch thì thành danh sách liên kết, `O(n)`. Phần còn lại của bài là các cách giữ cây thấp: phép xoay (AVL, red-black), nới lỏng thứ tự để có cấu trúc đơn giản hơn (heap), và làm cây rộng ra thay vì cao lên (B-tree, nền của chỉ mục cơ sở dữ liệu).

## Cây nhị phân và bốn cách duyệt

Một <Term>tree</Term> là các **nút** nối thành phân cấp: một nút **gốc**, mỗi nút có thể có con, không có vòng. **Cây nhị phân** cho mỗi nút tối đa hai con, trái và phải. Nút không có con là **lá**. **Chiều cao** là số nút trên đường dài nhất từ gốc tới lá.

**Duyệt** là đi qua mọi nút. Ba cách đầu chỉ khác ở thời điểm ghi nút hiện tại so với hai nhánh con; cách thứ tư đi theo từng tầng.

```python
class Node:
    __slots__ = ("key", "left", "right")
    def __init__(self, key, left=None, right=None):
        self.key, self.left, self.right = key, left, right

#         8
#       /   \
#      3     10
#     / \      \
#    1   6      14
root = Node(8, Node(3, Node(1), Node(6)), Node(10, None, Node(14)))

def preorder(n):                      # nút, trái, phải
    return [n.key] + preorder(n.left) + preorder(n.right) if n else []
def inorder(n):                       # trái, nút, phải
    return inorder(n.left) + [n.key] + inorder(n.right) if n else []
def postorder(n):                     # trái, phải, nút
    return postorder(n.left) + postorder(n.right) + [n.key] if n else []
def levelorder(n):                    # từng tầng, trái sang phải
    out, level = [], [n]
    while level:
        out += [x.key for x in level]
        level = [c for x in level for c in (x.left, x.right) if c]
    return out
```

**Đoán trước:** với cây trên, `inorder` cho dãy nào?

```python
for f in (preorder, inorder, postorder, levelorder):
    print(f"{f.__name__:<10}: {f(root)}")
```

```text
preorder  : [8, 3, 1, 6, 10, 14]
inorder   : [1, 3, 6, 8, 10, 14]
postorder : [1, 6, 3, 14, 10, 8]
levelorder: [8, 3, 10, 1, 6, 14]
```

`inorder` cho dãy **tăng dần**. Không phải trùng hợp: cây này là một BST, và với BST, đi trái hết rồi mới ghi nút rồi mới đi phải chính là đọc các khoá theo thứ tự. Mỗi cách duyệt có chỗ dùng riêng:

| Cách duyệt | Dùng để |
|---|---|
| preorder | chép cây hay ghi cây ra file: cha phải có trước con |
| inorder | đọc các khoá của BST theo thứ tự tăng dần |
| postorder | xoá cây, tính kích thước thư mục: con xong trước cha |
| levelorder | đi theo tầng, chính là BFS ở bài [Graph](/docs/dsa/graphs) |

**Thử ngay:** muốn tính tổng dung lượng của một thư mục, trong đó dung lượng mỗi thư mục bằng tổng các thư mục con cộng file của nó, nên duyệt theo cách nào?

<Expand title="Đáp án">

Postorder: phải tính xong mọi thư mục con rồi mới cộng được cho thư mục cha.

</Expand>

## Cây tìm kiếm nhị phân

BST là cây nhị phân thêm một quy tắc: với **mọi** nút, mọi khoá ở cây con trái nhỏ hơn khoá của nút, mọi khoá ở cây con phải lớn hơn. Tìm một khoá: bắt đầu ở gốc, bằng thì thấy, nhỏ hơn thì rẽ trái, lớn hơn thì rẽ phải, gặp chỗ trống thì không có. Chèn đi đúng đường đó và gắn nút mới vào chỗ trống cuối đường.

```python
class BST:
    def __init__(self): self.root = None
    def insert(self, key):                    # vòng lặp, không đệ quy, để cây lệch không tràn stack
        if self.root is None: self.root = Node(key); return
        cur = self.root
        while key != cur.key:
            side = "left" if key < cur.key else "right"
            if getattr(cur, side) is None:
                setattr(cur, side, Node(key)); return
            cur = getattr(cur, side)
    def find(self, key):                      # trả về (có không, số nút đã thăm)
        cur, steps = self.root, 0
        while cur:
            steps += 1
            if key == cur.key: return True, steps
            cur = cur.left if key < cur.key else cur.right
        return False, steps
    def height(self):
        h, level = 0, [self.root] if self.root else []
        while level:
            h += 1; level = [c for n in level for c in (n.left, n.right) if c]
        return h

def show(n, indent=0):                        # in cây nằm ngang: nhánh phải ở trên, nhánh trái ở dưới
    if n:
        show(n.right, indent + 4); print(" " * indent + str(n.key)); show(n.left, indent + 4)
```

**Đoán trước:** chèn `50, 30, 70, 20, 40, 60, 80`. Tìm `60` thăm mấy nút? Tìm `65` (không có) thì sao?

```python
t = BST()
for k in (50, 30, 70, 20, 40, 60, 80):
    t.insert(k)
show(t.root)
print("inorder:", inorder(t.root))
print("find(60):", t.find(60), "| find(65):", t.find(65))
```

```text
        80
    70
        60
50
        40
    30
        20
inorder: [20, 30, 40, 50, 60, 70, 80]
find(60): (True, 3) | find(65): (False, 3)
```

Đọc hình bằng cách nghiêng đầu sang trái: `50` là gốc, `70` ở trên là con phải, `30` ở dưới là con trái. Tìm `60`: `50`, rẽ phải sang `70`, rẽ trái sang `60`, ba nút. Tìm `65` cũng đi ba nút rồi gặp chỗ trống bên phải `60`. Bảy khoá, ba tầng: số bước bằng chiều cao, khoảng `log2 n`.

**Thử ngay:** trong BST, khoá nhỏ nhất nằm ở đâu? Tìm nó tốn bao nhiêu?

<Expand title="Đáp án">

Đi trái mãi từ gốc tới khi không còn con trái. Tốn đúng bằng chiều cao của nhánh đó, tức `O(chiều cao)`. Bảng băm không làm được việc này nhanh hơn `O(n)`.

</Expand>

## Xoá khỏi BST: ba ví dụ

Xoá khó hơn chèn, vì không được làm mất các nút con của nút bị xoá. Có ba trường hợp: nút là lá thì cắt đi; nút có một con thì cho con đó lên thế chỗ; nút có hai con thì không cắt được, mà thay khoá của nó bằng **kế nhiệm** (khoá nhỏ nhất của cây con phải: sang phải một bước rồi đi trái mãi), rồi xoá nút kế nhiệm. Nút kế nhiệm không có con trái, nên việc xoá nó rơi về một trong hai trường hợp đầu.

```python
def delete(n, key):                           # trả về gốc mới của cây con n
    if n is None: return None
    if key < n.key: n.left = delete(n.left, key)
    elif key > n.key: n.right = delete(n.right, key)
    else:
        if n.left is None: return n.right     # lá, hoặc chỉ có con phải
        if n.right is None: return n.left     # chỉ có con trái
        s = n.right                           # hai con: tìm kế nhiệm
        while s.left: s = s.left
        n.key = s.key                         # chép khoá kế nhiệm lên
        n.right = delete(n.right, s.key)      # rồi xoá nút kế nhiệm
    return n
```

### Ví dụ 1 (giải sẵn)

Từ cây `50, 30, 70, 20, 40, 60, 80` ở trên, xoá lần lượt `20`, `30`, `50`.

1. `20` là lá: cắt đi.
2. `30` lúc này chỉ còn một con là `40`: cho `40` lên thế chỗ `30`.
3. `50` có hai con. Kế nhiệm: sang phải tới `70`, đi trái tới `60`, `60` không có con trái nên dừng. Chép `60` lên gốc, rồi xoá nút `60` cũ (một lá).

```python

    t.root = delete(t.root, k)
    print(f"xoá {k}: inorder = {inorder(t.root)}")
show(t.root)
```

```text
xoá 20: inorder = [30, 40, 50, 60, 70, 80]
xoá 30: inorder = [40, 50, 60, 70, 80]
xoá 50: inorder = [40, 60, 70, 80]
        80
    70
60
    40
```

Sau mỗi lần xoá, `inorder` vẫn tăng dần: quy tắc BST được giữ.

## Chiều cao phụ thuộc thứ tự chèn

BST không tự sắp xếp lại hình dạng của nó. Khoá đầu tiên luôn là gốc, và mỗi khoá sau nằm ở đâu là do các khoá trước quyết định.

**Đoán trước:** chèn 4.000 khoá theo thứ tự tăng dần `0, 1, 2, ...`. Cây cao bao nhiêu? Nếu chèn cùng các khoá đó theo thứ tự ngẫu nhiên thì sao?

```python
import random, math
random.seed(2)
print(f"{'n':>7} | {'chèn ngẫu nhiên: cao':>20} | {'log2 n':>6} | {'chèn tăng dần: cao':>18}")
for n in (1_000, 4_000):
    keys = list(range(n))
    a = BST(); random.shuffle(keys)
    for k in keys: a.insert(k)
    b = BST()
    for k in sorted(keys): b.insert(k)
    print(f"{n:>7} | {a.height():>20} | {math.log2(n):>6.1f} | {b.height():>18}")
```

```text
      n | chèn ngẫu nhiên: cao | log2 n | chèn tăng dần: cao
   1000 |                   23 |   10.0 |               1000
   4000 |                   28 |   12.0 |               4000
```

Chèn ngẫu nhiên cho cây cao khoảng hai tới ba lần `log2 n`, vẫn là `O(log n)`. Chèn tăng dần thì mỗi khoá mới lớn hơn mọi khoá cũ, luôn đi sang phải tới cuối: cây thành một đường thẳng cao đúng `n`, tức một danh sách liên kết, và mọi thao tác thành `O(n)`.

**Hiểu lầm hay gặp ở đây:** nhiều người nghĩ BST luôn cho `O(log n)`. Thật ra BST thường chỉ cho `O(chiều cao)`, và chiều cao có thể bằng `n`. Dữ liệu đến theo thứ tự lại rất hay gặp: ID tự tăng, dấu thời gian, tên đã sắp theo bảng chữ cái. Cần một cây **tự cân bằng**.

**Thử ngay:** chèn `1, 2, 3, ..., 1.000.000` vào BST thường, rồi tìm `1.000.000`. Thăm bao nhiêu nút?

<Expand title="Đáp án">

Một triệu nút: cây là một đường thẳng sang phải, và `1.000.000` nằm ở cuối. Cây cân bằng chỉ cần khoảng 20.

</Expand>

## Giữ cây thấp bằng phép xoay: AVL

**Phép xoay** đổi hình dạng một đoạn cây mà giữ nguyên thứ tự inorder, chỉ bằng cách đổi vài con trỏ:

```text
   xoay phải tại y                 xoay trái tại x
       y             x                x                y
      / \           / \              / \              / \
     x   C   ->    A   y            A   y     ->     x   C
    / \               / \              / \          / \
   A   B             B   C            B   C        A   B
```

Hai phía đều đọc ra `A, x, B, y, C` khi duyệt inorder, nên đều là BST hợp lệ, nhưng chiều cao khác nhau. Xoay phải kéo `x` lên một tầng, đẩy `y` xuống.

<Term>AVL tree</Term> (Adelson-Velsky và Landis, 1962) giữ một bất biến: tại **mọi** nút, chiều cao cây con trái và cây con phải lệch nhau **tối đa 1**. Sau mỗi lần chèn, đi ngược lên từ chỗ vừa chèn; nút nào lệch 2 thì sửa bằng một phép xoay, hoặc hai phép nếu nhánh lệch bị gấp khúc.

<Expand title="Code AVL (chèn và kiểm tra bất biến)">

```python
class AVLNode:
    __slots__ = ("key", "left", "right", "h")
    def __init__(self, key): self.key, self.left, self.right, self.h = key, None, None, 1

def ht(n): return n.h if n else 0
def upd(n): n.h = 1 + max(ht(n.left), ht(n.right))
def bal(n): return ht(n.left) - ht(n.right)

rotations = 0
def rot_right(y):
    global rotations; rotations += 1
    x = y.left; y.left, x.right = x.right, y; upd(y); upd(x); return x
def rot_left(x):
    global rotations; rotations += 1
    y = x.right; x.right, y.left = y.left, x; upd(x); upd(y); return y

def avl_insert(n, key):
    if n is None: return AVLNode(key)
    if key < n.key: n.left = avl_insert(n.left, key)
    elif key > n.key: n.right = avl_insert(n.right, key)
    else: return n
    upd(n)
    if bal(n) > 1:                            # lệch trái
        if bal(n.left) < 0: n.left = rot_left(n.left)      # gấp khúc trái-phải: xoay đôi
        return rot_right(n)
    if bal(n) < -1:                           # lệch phải
        if bal(n.right) > 0: n.right = rot_right(n.right)  # gấp khúc phải-trái: xoay đôi
        return rot_left(n)
    return n

def check_avl(n, lo=-math.inf, hi=math.inf):  # kiểm bất biến AVL và thứ tự BST, trả về chiều cao
    if n is None: return 0
    assert lo < n.key < hi, "sai thứ tự BST"
    hl, hr = check_avl(n.left, lo, n.key), check_avl(n.right, n.key, hi)
    assert abs(hl - hr) <= 1, "lệch quá 1"
    return 1 + max(hl, hr)
```

</Expand>

**Đoán trước:** chèn `1, 2, 3, 4, 5, 6, 7` tăng dần vào AVL. Cây trông thế nào?

```python
r = None
for k in range(1, 8):
    r = avl_insert(r, k)
show(r)
print("số lần xoay:", rotations)
```

```text
        7
    6
        5
4
        3
    2
        1
số lần xoay: 4
```

Bảy khoá tăng dần, thứ tự tệ nhất với BST thường, cho ra cây đầy ba tầng với `4` ở gốc. Mỗi lần chèn làm nhánh phải dài thêm, và một phép xoay trái kéo nút giữa lên.

Với dữ liệu lớn, `check_avl` kiểm cả hai bất biến sau khi chèn xong:

```python
print(f"{'n':>8} | {'AVL, chèn tăng dần: cao':>24} | {'AVL, chèn ngẫu nhiên: cao':>26} | {'log2 n':>6}")
for n in (1_000, 100_000):
    rotations = 0; r = None
    for k in range(n): r = avl_insert(r, k)
    h_sorted = check_avl(r)
    keys = random.sample(range(10 * n), n); r2 = None
    for k in keys: r2 = avl_insert(r2, k)
    print(f"{n:>8} | {h_sorted:>24} | {check_avl(r2):>26} | {math.log2(n):>6.1f}")
```

```text
       n |  AVL, chèn tăng dần: cao |  AVL, chèn ngẫu nhiên: cao | log2 n
    1000 |                       10 |                         12 |   10.0
  100000 |                       17 |                         20 |   16.6
```

Chèn tăng dần 100.000 khoá, cây vẫn chỉ cao 17, sát `log2 n`. Bất biến "lệch tối đa 1" bảo đảm chiều cao không quá khoảng `1,44 × log2 n`, nên mọi thao tác là `O(log n)` dù dữ liệu đến theo thứ tự nào.

**Red-black tree** là lựa chọn phổ biến hơn trong thư viện chuẩn (`std::map` của C++, `TreeMap` của Java, kernel Linux). Nó cho mỗi nút một bit màu và nới lỏng điều kiện cân bằng: cây có thể cao tới `2 × log2 n`, đổi lại mỗi lần chèn hay xoá cần ít phép xoay hơn.

| | AVL | Red-black |
|---|---|---|
| Chiều cao tối đa | khoảng `1,44 log2 n` | khoảng `2 log2 n` |
| Tìm | nhanh hơn một chút | chậm hơn một chút |
| Chèn, xoá | xoay nhiều hơn | tối đa vài phép xoay và đổi màu |
| Hợp với | đọc nhiều, ghi ít | đọc ghi lẫn lộn |

Cả hai đều `O(log n)` cho mọi thao tác. Bản cài red-black nằm ở phần Đi sâu hơn.

**Thử ngay:** chèn `3, 1, 2` vào AVL. Cây lệch kiểu gì, và cần mấy phép xoay?

<Expand title="Đáp án">

`3` có con trái `1`, `1` có con phải `2`: lệch trái nhưng gấp khúc. Cần hai phép xoay: xoay trái tại `1` để duỗi thẳng thành `3 → 2 → 1`, rồi xoay phải tại `3`. Kết quả: `2` ở gốc, `1` và `3` hai bên.

</Expand>

## Heap: chỉ cần phần tử nhỏ nhất

Nhiều bài toán không cần toàn bộ thứ tự, chỉ cần **phần tử nhỏ nhất lúc này**: bộ lập lịch lấy việc có hạn chót sớm nhất, Dijkstra lấy đỉnh gần nhất, lấy top 10 trong một dòng dữ liệu. <Term>Priority queue</Term> là giao diện cho việc đó: `push(x)` và `pop()` trả về phần tử nhỏ nhất. Cách cài thường dùng là <Term>heap</Term> nhị phân.

Min-heap là cây nhị phân thoả hai điều: **mỗi nút nhỏ hơn hoặc bằng hai con của nó**, và cây **đầy từ trái sang**, chỉ tầng cuối được thiếu ở bên phải. Nó lỏng hơn BST nhiều: hai anh em không có thứ tự gì với nhau, chỉ biết chắc gốc là nhỏ nhất.

Vì cây luôn đầy từ trái, không cần con trỏ: lưu thẳng theo tầng vào một mảng. Nút ở vị trí `i` có cha ở `(i-1) // 2` và hai con ở `2i+1`, `2i+2`.

- **`push`**: thêm vào cuối mảng, rồi đổi chỗ với cha chừng nào còn nhỏ hơn cha (sift-up).
- **`pop`**: lấy gốc ra, đưa phần tử cuối lên gốc, rồi đổi chỗ với con **nhỏ hơn** chừng nào còn lớn hơn nó (sift-down).

Cây đầy có chiều cao `log2 n`, nên cả hai thao tác là `O(log n)`.

<Expand title="Code min-heap">

```python
class MinHeap:
    def __init__(self, items=()):
        self.a, self.cmp = list(items), 0     # cmp đếm số lần so sánh
    def push(self, x):
        a = self.a; a.append(x); i = len(a) - 1
        while i > 0:                          # sift-up
            p = (i - 1) // 2; self.cmp += 1
            if a[p] <= a[i]: break
            a[p], a[i] = a[i], a[p]; i = p
    def _sift_down(self, i):
        a, n = self.a, len(self.a)
        while True:
            l, r, m = 2 * i + 1, 2 * i + 2, i
            if l < n:
                self.cmp += 1
                if a[l] < a[m]: m = l
            if r < n:
                self.cmp += 1
                if a[r] < a[m]: m = r
            if m == i: return
            a[i], a[m] = a[m], a[i]; i = m
    def pop(self):
        a = self.a; top = a[0]; last = a.pop()
        if a: a[0] = last; self._sift_down(0)
        return top
```

</Expand>

**Đoán trước:** `push` lần lượt `5, 3, 8, 1, 9, 2, 7`. Phần tử đầu mảng là gì? Mảng có được sắp xếp không?

```python
h = MinHeap()
for x in (5, 3, 8, 1, 9, 2, 7): h.push(x)
print("mảng heap:", h.a)
print("pop lần lượt:", [h.pop() for _ in range(7)])
```

```text
mảng heap: [1, 3, 2, 5, 9, 8, 7]
pop lần lượt: [1, 2, 3, 5, 7, 8, 9]
```

`a[0] = 1` là nhỏ nhất, nhưng mảng **không** được sắp xếp: `3` ở vị trí 1 lớn hơn `2` ở vị trí 2. Chỉ cần mỗi nút nhỏ hơn con của nó: hai con của `1` là `3` và `2`; hai con của `3` (vị trí 3 và 4) là `5` và `9`; hai con của `2` (vị trí 5 và 6) là `8` và `7`. `pop` liên tục thì ra dãy tăng dần; đó là **heapsort**, `O(n log n)`.

**Hiểu lầm hay gặp ở đây:** nhiều người nghĩ heap là cấu trúc có thứ tự như BST, nên tìm một khoá bất kỳ cũng nhanh. Thật ra heap chỉ biết gốc nhỏ nhất. Tìm một khoá bất kỳ phải duyệt cả mảng, `O(n)`, và duyệt mảng heap không cho dãy tăng dần.

Còn một điều bất ngờ: xây heap từ `n` phần tử có sẵn không cần `n` lần `push`. Đặt cả mảng vào rồi gọi sift-down từ nút cha cuối cùng ngược về gốc (heapify).

**Đoán trước:** heapify một triệu phần tử tốn khoảng bao nhiêu lần so sánh: cỡ `2n`, hay cỡ `n log2 n` (khoảng 20 triệu)?

```python
def heapify(items):
    h = MinHeap(items)
    for i in range(len(h.a) // 2 - 1, -1, -1):
        h._sift_down(i)
    return h

for n in (1_000, 100_000, 1_000_000):
    data = [random.random() for _ in range(n)]
    hp = heapify(data)
    assert hp.a[0] == min(data)
    print(f"n={n:>9,}: heapify {hp.cmp:>9,} lần so sánh  (2n = {2 * n:>9,}, n·log2 n = {round(n * math.log2(n)):>10,})")
```

```text
n=    1,000: heapify     1,885 lần so sánh  (2n =     2,000, n·log2 n =      9,966)
n=  100,000: heapify   187,809 lần so sánh  (2n =   200,000, n·log2 n =  1,660,964)
n=1,000,000: heapify 1,882,201 lần so sánh  (2n = 2,000,000, n·log2 n = 19,931,569)
```

Dưới `2n`: heapify là `O(n)`. Lý do: một nửa số nút là lá, không phải sift gì; một phần tư chỉ sift tối đa một tầng; một phần tám tối đa hai tầng. Phần lớn nút nằm sát đáy, nơi sift-down rất ngắn. Python có sẵn `heapq` (min-heap trên `list`) với `heappush`, `heappop`, `heapify`.

**Thử ngay:** phần tử ở vị trí 6 của mảng heap có cha ở vị trí nào? Mảng `[2, 5, 3, 4, 6]` có phải min-heap không?

<Expand title="Đáp án">

Cha ở `(6 - 1) // 2 = 2`. Mảng `[2, 5, 3, 4, 6]` không phải heap: vị trí 3 (giá trị `4`) có cha ở vị trí 1 (giá trị `5`), mà `5 > 4`.

## B-tree: cây rộng cho dữ liệu trên đĩa

Cây AVL một tỷ khoá cao khoảng 30 tầng. Trong RAM thì ổn. Trên đĩa thì không: mỗi tầng là một lần đọc một **trang** (thường 4 hay 8 KB) ở vị trí khác, và đọc một trang tốn gần như bằng đọc một byte. Chi phí đo bằng **số trang phải đọc**, không phải số phép so sánh. Vậy hãy cho mỗi nút chứa đầy một trang, tức hàng trăm khoá, để cây rộng ra và thấp xuống.

<Term>B-tree</Term> (Bayer và McCreight, 1972) với bậc `t` cho mỗi nút (trừ gốc) từ `t-1` tới `2t-1` khoá đã sắp xếp; nút trong có số con bằng số khoá cộng một, và các khoá chia khoảng cho các con. **Mọi lá nằm cùng độ sâu.** Chèn vào lá; nút đầy thì **tách** làm đôi và đẩy khoá giữa lên cha. Cây chỉ cao thêm khi gốc bị tách, nên không bao giờ lệch.

<Expand title="Code B-tree (tìm, chèn, tách nút)">

```python
import bisect

class BNode:
    def __init__(self, leaf): self.keys, self.kids, self.leaf = [], [], leaf

class BTree:
    def __init__(self, t):
        self.t, self.root, self.reads = t, BNode(True), 0
    def search(self, key):
        n = self.root
        while True:
            self.reads += 1                           # mỗi nút là một trang đọc từ đĩa
            i = bisect.bisect_left(n.keys, key)
            if i < len(n.keys) and n.keys[i] == key: return True
            if n.leaf: return False
            n = n.kids[i]
    def insert(self, key):
        r = self.root
        if len(r.keys) == 2 * self.t - 1:             # gốc đầy: tách, cây cao thêm 1 tầng
            s = BNode(False); s.kids = [r]; self.root = s; self._split(s, 0)
        n = self.root
        while True:
            i = bisect.bisect_left(n.keys, key)
            if i < len(n.keys) and n.keys[i] == key: return
            if n.leaf: n.keys.insert(i, key); return
            if len(n.kids[i].keys) == 2 * self.t - 1: # tách con đầy trước khi đi xuống
                self._split(n, i)
                if key > n.keys[i]: i += 1
                elif key == n.keys[i]: return
            n = n.kids[i]
    def _split(self, parent, i):
        t, y = self.t, parent.kids[i]; z = BNode(y.leaf)
        mid = y.keys[t - 1]
        z.keys, y.keys = y.keys[t:], y.keys[:t - 1]
        if not y.leaf: z.kids, y.kids = y.kids[t:], y.kids[:t]
        parent.keys.insert(i, mid); parent.kids.insert(i + 1, z)
    def height(self):
        h, n = 1, self.root
        while not n.leaf: n = n.kids[0]; h += 1
        return h

def dump(n, d=0):
    print("  " * d + str(n.keys))
    for k in n.kids: dump(k, d + 1)

bt = BTree(2)                                     # mỗi nút 1 tới 3 khoá
for k in range(1, 11): bt.insert(k)
dump(bt.root)
```

</Expand>

```text
[4]
  [2]
    [1]
    [3]
  [6, 8]
    [5]
    [7]
    [9, 10]
```

Mười khoá chèn tăng dần, nhưng mọi lá (`[1]`, `[3]`, `[5]`, `[7]`, `[9, 10]`) nằm cùng độ sâu: B-tree cân bằng hoàn hảo nhờ chỉ lớn lên ở gốc.

**Đoán trước:** 200.000 khoá, mỗi nút chứa tối đa 127 khoá (`t = 64`). Tìm một khoá đọc trung bình bao nhiêu trang? Cây nhị phân cân bằng cần khoảng 18.

```python
random.seed(6)
N = 200_000
keys = random.sample(range(10 * N), N)
print(f"{'t':>4} {'khoá/nút tối đa':>16} {'chiều cao':>10} {'trang đọc TB mỗi lần tìm':>25}")
for t in (2, 8, 64, 256):
    b = BTree(t)
    for k in keys: b.insert(k)
    b.reads = 0
    for k in keys[:20_000]: b.search(k)
    print(f"{t:>4} {2 * t - 1:>16} {b.height():>10} {b.reads / 20_000:>25.2f}")
```

```text
   t  khoá/nút tối đa  chiều cao  trang đọc TB mỗi lần tìm
   2                3         14                     12.00
   8               15          6                      5.68
  64              127          3                      2.96
 256              511          3                      2.99
```

Với 127 khoá mỗi nút, cây chỉ cao 3 tầng và mỗi lần tìm đọc khoảng 3 trang, thay vì 18. Trang thật 8 KB chứa vài trăm khoá, nên một tỷ khoá cũng chỉ 4 tới 5 tầng, và vài tầng trên cùng thường nằm sẵn trong RAM.

Cơ sở dữ liệu và file system dùng biến thể **B+ tree**: chỉ lá chứa dữ liệu (hoặc con trỏ tới dòng dữ liệu), nút trong chỉ chứa khoá dẫn đường nên nhồi được nhiều khoá hơn; và các lá nối với nhau thành danh sách, nên tìm khoảng `[a, b]` chỉ cần tìm `a` rồi đi ngang qua các lá. Bài [Indexing](/docs/databases/indexing) đo B+ tree thật trong PostgreSQL: bảng một triệu dòng, chỉ mục 3 tầng.

**Thử ngay:** vì sao một chỉ mục trên đĩa không dùng cây AVL, dù AVL cũng `O(log n)`?

<Expand title="Đáp án">

`O(log n)` của AVL là `log2 n` lần đọc, mỗi lần một nút nhỏ ở một chỗ khác trên đĩa: một tỷ khoá là khoảng 30 lần đọc trang. B-tree có cơ số log là số khoá mỗi nút (hàng trăm), nên chỉ 4 tới 5 lần đọc. Big-O như nhau, nhưng hằng số chênh nhau sáu tới bảy lần, và mỗi lần đọc đĩa rất đắt.

</Expand>

## Trie: cây theo từng ký tự

Mọi cây ở trên so sánh **cả khoá** tại mỗi nút. Khi khoá là chuỗi, <Term>trie</Term> đi theo **từng ký tự**: mỗi cạnh mang một ký tự, đường từ gốc tới một nút có đánh dấu "kết thúc" là một từ. Các từ chung tiền tố dùng chung đoạn đường. Tìm một chuỗi dài `m` đi đúng `m` cạnh, không phụ thuộc có bao nhiêu từ.

**Đoán trước:** 8 từ dưới đây có tổng 26 ký tự. Trie của chúng có nhiều nút hơn hay ít hơn 26?

<Expand title="Code trie">

```python
class TrieNode:
    __slots__ = ("kids", "end")
    def __init__(self): self.kids, self.end = {}, False

class Trie:
    def __init__(self): self.root, self.nodes = TrieNode(), 1
    def insert(self, w):
        n = self.root
        for ch in w:
            if ch not in n.kids:
                n.kids[ch] = TrieNode(); self.nodes += 1
            n = n.kids[ch]
        n.end = True
    def with_prefix(self, p):                 # mọi từ bắt đầu bằng p, theo thứ tự chữ cái
        n = self.root
        for ch in p:
            n = n.kids.get(ch)
            if n is None: return []
        out, stack = [], [(n, p)]
        while stack:
            n, s = stack.pop()
            if n.end: out.append(s)
            for ch in sorted(n.kids, reverse=True): stack.append((n.kids[ch], s + ch))
        return out

tr = Trie()
words = ["car", "card", "care", "cart", "cat", "do", "dog", "dot"]
for w in words: tr.insert(w)
print(f"{len(words)} từ, {sum(map(len, words))} ký tự, trie có {tr.nodes} nút (kể cả gốc)")
for p in ("car", "ca", "do", "x"):
    print(f"tiền tố {p!r}: {tr.with_prefix(p)}")
```

</Expand>

```text
8 từ, 26 ký tự, trie có 12 nút (kể cả gốc)
tiền tố 'car': ['car', 'card', 'care', 'cart']
tiền tố 'ca': ['car', 'card', 'care', 'cart', 'cat']
tiền tố 'do': ['do', 'dog', 'dot']
tiền tố 'x': []
```

Ít hơn nhiều so với số ký tự, vì `car`, `card`, `care`, `cart`, `cat` dùng chung đoạn `c → a`. Trie hợp với việc gợi ý khi người dùng gõ từng ký tự, và với **khớp tiền tố dài nhất**: router chọn route cụ thể nhất cho một địa chỉ IP bằng một dạng trie (xem [IP & Routing](/docs/networking/ip-routing)).

**Hiểu lầm hay gặp ở đây:** nhiều người nghĩ cứ tìm theo tiền tố là nên dùng trie. Thật ra với một tập từ **ít thay đổi**, mảng đã sắp xếp cộng tìm nhị phân (`bisect`) tìm được vị trí đầu rồi đọc liền các từ kế tiếp, thường nhanh hơn và tốn ít bộ nhớ hơn nhiều, vì trie cài bằng một object và một dict cho mỗi nút. Trie thắng khi tập từ thay đổi liên tục, hoặc khi cần đi từng ký tự.

**Thử ngay:** thêm từ `"ca"` vào trie trên. Có thêm nút nào không?

<Expand title="Đáp án">

Không. Đường `c → a` đã có sẵn; chỉ cần đánh dấu `end = True` ở nút `a`.

</Expand>

3. Bảng băm: tìm, chèn, xoá `O(1)` trung bình, nhưng tìm khoảng phải duyệt cả bảng. Heap: chỉ lấy nhỏ nhất nhanh, tìm khoá bất kỳ `O(n)`. Cây cân bằng: mọi thao tác `O(log n)`, tìm khoảng `O(log n + số kết quả)` nhờ duyệt inorder từ `a`. Chọn cây cân bằng.
4. `heapify` chỉ sắp mảng thành heap, không sắp xếp: in ra `[1, 3, 8, 5, 9]`, chưa tăng dần. Phải `heappop` liên tục, hoặc dùng `sorted(h)`.
5. Mỗi nút tối đa 256 con, và `256^3 ≈ 16,8 triệu`, nên cây khoảng 3 tới 4 tầng (nút thường không đầy hẳn): đọc 3 tới 4 trang. Hai tầng trên trong RAM thì chỉ còn 1 tới 2 lần đọc đĩa.

## Đi sâu hơn

Các phần dưới không cần để đọc tiếp chặng DSA.

<Expand title="Red-black tree nghiêng trái (LLRB) trong 20 dòng">

Red-black tree tương đương với **2-3-4 tree** (mỗi nút giữ 1 tới 3 khoá) viết bằng cây nhị phân: nút đen cùng các con đỏ nối liền tạo thành một nút lớn. Luật: gốc đen; nút đỏ không có con đỏ; mọi đường từ một nút xuống lá rỗng đi qua cùng số nút đen. Hai luật cuối cho chiều cao tối đa `2 log2(n+1)`. Biến thể **left-leaning** của Sedgewick thêm luật "cạnh đỏ luôn nghiêng trái", và phần cân bằng khi chèn chỉ còn ba câu `if`:

```python
RED, BLACK = True, False

class RB:
    __slots__ = ("key", "left", "right", "color")
    def __init__(self, key): self.key, self.left, self.right, self.color = key, None, None, RED

def red(n): return n is not None and n.color == RED
def rl(h):
    x = h.right; h.right, x.left = x.left, h; x.color, h.color = h.color, RED; return x
def rr(h):
    x = h.left; h.left, x.right = x.right, h; x.color, h.color = h.color, RED; return x
def flip(h):
    h.color, h.left.color, h.right.color = RED, BLACK, BLACK

def rb_insert(h, key):
    if h is None: return RB(key)
    if key < h.key: h.left = rb_insert(h.left, key)
    elif key > h.key: h.right = rb_insert(h.right, key)
    if red(h.right) and not red(h.left): h = rl(h)
    if red(h.left) and red(h.left.left): h = rr(h)
    if red(h.left) and red(h.right): flip(h)
    return h

def rb_check(h):                               # trả về (chiều cao đen, chiều cao)
    if h is None: return 1, 0
    assert not (red(h) and (red(h.left) or red(h.right))) and not red(h.right)
    (bl, hl), (br, hr) = rb_check(h.left), rb_check(h.right)
    assert bl == br, "chiều cao đen khác nhau"
    return bl + (0 if red(h) else 1), 1 + max(hl, hr)

for n in (1_000, 100_000):
    r = None
    for k in range(n): r = rb_insert(r, k); r.color = BLACK
    r2 = None
    for k in random.sample(range(10 * n), n): r2 = rb_insert(r2, k); r2.color = BLACK
    print(f"n={n:>7,}: chèn tăng dần cao {rb_check(r)[1]}, chèn ngẫu nhiên cao {rb_check(r2)[1]}, cận 2·log2(n+1) = {2 * math.log2(n + 1):.1f}")
```

```text
n=  1,000: chèn tăng dần cao 10, chèn ngẫu nhiên cao 13, cận 2·log2(n+1) = 19.9
n=100,000: chèn tăng dần cao 17, chèn ngẫu nhiên cao 23, cận 2·log2(n+1) = 33.2
```

Bản xoá của LLRB dài hơn nhiều nên không cài ở đây. Kernel Linux dùng red-black tree (`rbtree`) cho scheduler CFS, nơi các task xếp theo thời gian đã chạy để lấy ngay task chạy ít nhất (xem [CPU Scheduling](/docs/os/cpu-scheduling)).

</Expand>

<Expand title="Vì sao heapify là O(n): tổng chuỗi">

Với `n` nút, có khoảng `n/4` nút cách lá một tầng, `n/8` nút cách hai tầng, và cứ thế. Sift-down từ nút cách lá `k` tầng tốn tối đa `k` bước. Tổng số bước:

```text
n/4·1 + n/8·2 + n/16·3 + ... = n · Σ k/2^(k+1) = n · 1 = n
```

Mỗi bước tốn tối đa hai phép so sánh, nên tổng dưới `2n`, khớp với số đo ở mục Heap.

</Expand>

<Expand title="Chiều cao B-tree với trang 4 KB">

Số khoá mỗi nút quyết định chiều cao: `⌈log_{fan-out} n⌉`.

| Khoá + con trỏ | Khoá mỗi trang 4 KB | `10^6` khoá | `10^9` khoá | `10^12` khoá |
|---|---|---|---|---|
| 8 B + 8 B | khoảng 256 | 3 tầng | 4 tầng | 5 tầng |
| 16 B + 8 B | khoảng 170 | 3 tầng | 5 tầng | 6 tầng |
| 64 B + 8 B | khoảng 56 | 4 tầng | 6 tầng | 7 tầng |

Khoá dài làm cây cao thêm; đây là một lý do chỉ mục trên cột chuỗi dài tốn hơn chỉ mục trên số nguyên. Bài [Indexing](/docs/databases/indexing) tính đúng số khoá mỗi trang của PostgreSQL từ kích thước tuple.

</Expand>

<Expand title="Cây có thứ tự trong các hệ thống thật">

- **Thư viện chuẩn**: `std::map`, `std::set` của C++ và `TreeMap` của Java là red-black tree; `BTreeMap` của Rust là B-tree, vì B-tree thân thiện cache hơn cây nhị phân ngay cả trong RAM. Python không có cây cân bằng trong thư viện chuẩn; người ta dùng `bisect` trên list đã sắp xếp hoặc `sortedcontainers`.
- **Redis sorted set** dùng **skip list**: danh sách liên kết nhiều tầng với các "đường tắt" chọn ngẫu nhiên, cho `O(log n)` kỳ vọng với code đơn giản hơn cây cân bằng.
- **Kernel Linux**: red-black tree cho scheduler CFS và nhiều nơi khác; các vùng nhớ ảo của process (xem [Virtual Memory](/docs/os/virtual-memory)) chuyển từ red-black sang maple tree từ Linux 6.1.
- **File system**: XFS, btrfs và NTFS dùng B+ tree cho thư mục và extent (xem [File Systems](/docs/os/file-systems)).
- **Heap**: `heapq` của Python, `priority_queue` của C++; bộ hẹn giờ của các runtime giữ hạn gần nhất ở gốc heap.

</Expand>
